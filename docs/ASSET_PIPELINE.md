# 3D 에셋 교체 파이프라인

## 현재 경로

`src/scene/assets.ts`의 MODEL_REGISTRY에 Kind별 glTF/GLB 경로·scale·offset·rotation·pivot·그림자·LOD 경로·materialSlots·clips·fallback을 기록한다. 현재 연결된 외부 파일은 직접 제작한 `public/models/ballast.gltf` 하나이며, 외부 구매 에셋이 아니다. 나머지는 절차형 모델이다. LOD 경로와 clip 목록은 등록 형식이며, 자동 애니메이션 재생기는 아직 없다.

GLTFLoader를 필요할 때만 동적으로 로드한다. 같은 경로는 한 번만 요청한다. 성공 시 모델을 복제해 템플릿으로 넣고 동일 재질을 병합한 후 인스턴싱한다. HTTP 실패·파싱 오류·빈 모델·논리 범위 초과는 해당 시설의 절차형 모델로 복구한다. 실패를 도시 삭제나 저장 실패로 전파하지 않는다. 런타임 재시도는 페이지 재시작 후 가능하다.

## 제작 규격

- 1 단위 = 한 타일의 가로 길이. 타일 1×1, 모델은 최대 0.98×0.98 안에 둔다. 여러 칸 건물은 현재 타일 단위 템플릿을 사용한다.
- +Y 위, +Z 정면, 원점은 바닥 중심. Y 최솟값 ≥ -0.01, 최댓값 ≤ PHYSICAL[kind].height.
- scale·rotation을 내보내기 전에 적용한다. 노멀을 정리하고, 불필요한 내부 면과 숨은 오브젝트를 제거한다.
- 일반 건물 권장 500–2,000 triangles, 주요 코어·항구 3,000 이하. 이는 권장 예산이며 현재 로더의 자동 제한은 공간 범위이다.
- PBR baseColor/metallic/roughness/emissive, 색 텍스처 sRGB, 노멀·roughness 선형. 원본 1K 이하, 소형 반복 건물 512 이하 권장.
- UV는 겹침과 이음새를 확인한다. 텍스처 아틀라스와 공유 재질을 우선한다. 한 시설당 재질 2–6개 권장.
- 정적 시설에는 리깅·스킨·애니메이션을 넣지 않는다. 미래 clip 이름은 Idle/Operate/Build/Damage/Repair로 기록하되 실제 게임 상태와 연결되기 전에는 재생하지 않는다.
- 라이선스·원작자·다운로드 출처·재배포 조건을 PR에 기록한다. 비밀 토큰을 모델 경로나 저장소에 넣지 않는다.

## 검증

정상 파일과 요청 차단 파일을 실제 브라우저에서 각각 검사한다. 동일 도시 저장을 전후 비교하고 건축·철거·업그레이드·다층·온라인을 재검증한다. 크기가 맞지 않는 모델을 scale로 억지로 줄이기 전에 원점·노멀·모델 경계를 확인한다. 공유 재질은 개별 ghost에서 직접 수정하지 않고 복제한다. 템플릿 병합 geometry는 컴포넌트 정리 시 해제하며 모듈 공유 재질·GLTF 캐시는 페이지 수명 동안 유지한다.

공식 API 참고: [Three.js GLTFLoader](https://threejs.org/docs/pages/GLTFLoader.html), [WebGLRenderer](https://threejs.org/docs/pages/WebGLRenderer).
