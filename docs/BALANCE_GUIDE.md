# 밸런스 규칙과 재현

Phase 11 · v0.11.0. 능력치·한도는 src/data/rules.ts 한 곳에 있으며 cityRules.ts는 재수출 호환 모듈이다. 렌더링은 생산·점유·질량·점수를 결정하지 않는다.

## 변경과 유지

이번 변경은 필수 공급의 장기 공백, 식량 소진 예상의 구역 혼합, 긴급 경고 누락과 지원 비용 낭비를 교정한다. 시설 ID·크기·질량·생산·유지비·부양 출력, 캠페인 30개의 이름·목표·별 조건과 재난 피해 상수는 유지했다. 사람의 전략 선호 자료 없이 전체 수치를 일괄 배율로 바꾸지 않았다.

BALANCE: solo 2 / campaign 1 / disaster 1 / supply 2. 온라인은 ONLINE.version 2이다. 식량 지원의 저장 공간 검사 변경이 서버에도 적용되므로 별도 버전을 올렸다. 기존 온라인 기록의 점수를 재계산하지 않으며 실행 중인 서버는 해당 프로세스 규칙을 계속 사용한다. 서버 교체 시 기존 운영 정책대로 진행 경기는 무효 처리된다.

## 오프라인 공급 v2

새 게임의 supply.version=2와 recent(최대 24개)를 저장한다. 같은 시드·상태·맥락은 같은 결과다. 부족한 부양·전력·식량·도로·공간의 기본 블록을 최근 8회부터 우선하고 오래 기다린 종류를 먼저 선택한다. 필요가 지속되고 종류가 해금되어 있으면 최대 12회 안에 공급한다. 도시 티어와 세계 기술 잠금에 맞지 않는 잔여 bag 항목도 제외한다. 비스크립트 공급의 같은 종류 연속은 2회까지다. 급한 기본 시설을 제공해도 자원·배치·실제 가동 비용은 그대로 든다.

캠페인 스크립트, 훈련 순서, 온라인의 고정 맥락 공급은 변경하지 않는다. 온라인 두 선수에게 동일한 시드 공급을 제공하며 개인 부족량으로 재배열하지 않는다. 기존 저장에 공급 버전이 없으면 기존 알고리즘으로 계속 진행한다. 버전만 있고 기록이 없거나 알 수 없는 버전이면 안전하게 거부한다.

## 경제·구조 경계

도로 구역별 재고·주민·노동자·발전·배터리를 그대로 계산한다. 식량 소진 예상은 주민이 있는 각 구역의 재고 / 순소비 중 가장 짧은 시간이다. 순생산이 음수가 아닌 구역은 ∞이며, 고립 구역의 생산은 다른 구역을 구하지 않는다. UI 상단의 재고는 코어 접근 가능 재고라는 기존 설명을 유지한다.

긴급 식량 80은 코어 연결 창고에 80의 빈 공간, 45크레딧, 60초 재사용 간격이 필요하다. 전력 지원은 자재15/크레딧35/에테르2로 +30을 20초 제공하고 90초 대기한다. 구호금은 잔액100 미만이며 난이도별 3/1/0회이다. UI와 실제 실행이 같은 supportReason 함수를 사용한다.

전체 부양 부족과 국소 하중 초과는 각각 경고한다. 코어 손상, 전력·식량 위기, 실제 재난은 동시에 표시할 수 있다. 위험을 숨기는 조작으로 게임 상태를 바꾸지 않는다.
