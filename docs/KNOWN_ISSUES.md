# 알려진 제약 · Phase 11

- 인간 초보자/숙련자 플레이 테스트, 재미·완주율·전략 승률 측정은 미실시다. 자동 엔진 검사와 실제 브라우저 조작만 수행한다.
- 여섯 단순 정책×3시드를 같은 온라인 자원·공급·60초 조건에서 검사했지만 인간 전략 경쟁 및 모든 캠페인의 복수 시드 해법은 완전히 검증하지 않았다. 고정 해법의 달성 가능성과 온라인 동등 공급은 별도로 검사한다.
- 기존 도시·시설 수치를 전체 재조정하지 않았다. 저장 도시의 질량/전력/생산을 갑자기 바꾸지 않는다. 균형 최적점을 찾았다는 주장은 하지 않는다.
- 최초 baseline의 research 시나리오는 존재하지 않는 기술 ID로 연구가 시작되지 않았고 trade는 수요가 없어 배송0이었다. 이 결과는 원자료로 보존하며 추가 research-running/trade-delivery 측정과 구분한다.
- 글자 확대는 핵심 인터페이스 중심이다. 전체 모바일 대응·임의 키 매핑·모든 글자/패널의 확대 배치·보조 기기 검증은 남아 있다.
- 조언은 규칙 기반 문구와 실제 문제 값이다. 모든 문제에 대해 현재 자원으로 실행 가능한 최적 건설 위치까지 계산하는 자동 해결사는 아니다.
- 과거 Phase 10 전체 시설/선박/지도 아트 완성과 후처리·시네마틱 범위는 PHASE10-REPORT.md의 제한을 따른다. SwiftShader FPS 감소를 숨기지 않았으며 실제 GPU 측정이 필요하다.
- Node SQLite 실험 경고, Three 대형 청크 권고와 npm audit의 기존 취약성 항목은 남아 있다. 별도 검토 없이 강제 major 업데이트를 적용하지 않았다.
- 공개 인터넷 배포·DNS 변경·PR 병합은 수행하지 않았다. 실제 WAN 지연, 장시간 서버 운영과 물리 기기별 성능은 미검증이다.

- 전략 검사에서 현재 온라인 공급에 수직 구조재와 재난 방어 전용 시설이 없음을 확인했다. vertical 정책은0배치였고, 방어 정책은 기본 지원 시설만 활용했다. 싱글플레이의 수직/방어 기능 전체가 온라인 전략으로 열려 있다는 주장은 하지 않는다.
