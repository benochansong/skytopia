# SKY RIVALS 운영 및 개발

## 실행

Node 24와 npm을 사용한다. `node:sqlite`가 실행 환경에 필요하며 현재 Node 24는 실험적 API 경고를 출력한다. 브라우저 클라이언트만 실행할 때는 기존 Node 22.12 이상 조건이 유지된다.

```powershell
npm ci
npm run server:build
npm run server:start
# 다른 터미널
npm run dev -- --port 5188 --strictPort
```

개발 서버는 `npm run server:dev`로도 실행할 수 있다. 이 명령은 셸 환경 변수를 사용한다. `.env`를 읽는 프로덕션 실행 명령은 `server:start`이다. 기본 서버는 loopback 8787, 클라이언트는 loopback 5188. Vite `/online` 프록시가 WebSocket 업그레이드를 전달한다. 5173 등 다른 포트를 쓰면 해당 클라이언트 origin을 `APP_ORIGIN`으로 서버에 설정한다.

`.env.example`을 `.env`로 복사하고 환경에 맞게 수정한다. `.env` 및 SQLite 데이터는 Git에서 제외한다. 서버 연결이 없어도 Phase 1–7은 동작한다. 온라인 메뉴의 연결 오류에서 싱글플레이로 돌아갈 수 있다.

## 두 브라우저

1. Chrome과 Edge, 또는 Chrome의 서로 다른 프로필/시크릿 컨텍스트에서 클라이언트를 연다. 동일 프로필의 두 탭은 같은 게스트 세션이라 두 플레이어가 되지 않는다.
2. 온라인 메뉴에서 각자 이름을 입력하고 연결한다.
3. A가 SKY DUEL 또는 CO-OP CITY 방을 만든다. B는 8자리 코드를 입력한다.
4. 둘 다 준비한 뒤 A가 시작한다. 3초 카운트다운 이후 서버 시간이 흐른다.
5. 포인터 또는 WASD로 위치, QE로 회전, Space로 배치한다. C는 보관, X는 블록 건너뛰기. 온라인 건너뛰기는 자재를 생성하지 않으며, 20초 만료도 같은 규칙이다.
6. 시설 선택 모드에서 시설을 클릭해 수리·보강·업그레이드한다. 협동 철거는 방장만 가능하고 확인 창이 표시된다. 핑을 클릭하면 해당 좌표로 카메라가 이동한다.
7. 대전은 10/15분, 붕괴, 포기, 60초 연결 유예 만료로 끝난다. 협동은 새 시설 4개, 인구 30, 안정 75%, 식량 자급, 전력 충족을 10초 유지하면 함께 승리한다.
8. 새로고침 후 다시 온라인 메뉴에서 연결하면 같은 세션과 경기로 복귀한다. 결과는 서버 DB에 보존되며 최근 20건을 조회한다.

`npx playwright test e2e/online.spec.ts --project=chrome`은 실제 서버와 서로 다른 두 브라우저 컨텍스트를 사용한다. 테스트는 클라이언트 상태를 읽지만 서버 상태·점수·승패를 조작하지 않는다. 서버 단위/통합 테스트만 가상 시간 함수를 호출하며 이 기능은 네트워크 API에 노출하지 않는다.

## 프로토콜과 신뢰 경계

- `/online` WebSocket, 프로토콜 v1. 게스트 세션은 서버가 발급한 256비트 임의 토큰이며 DB에는 SHA-256 해시만 저장한다. 토큰은 프런트엔드 온라인 전용 localStorage에 저장되고 로그·URL에 기록하지 않는다. 재접속 수명 30일. 이름 변경으로 다른 계정이 되지 않는다.
- HTTP `/health`는 `{ok,version}`만 제공한다. `/metrics`는 `Authorization: Bearer <ADMIN_TOKEN>`이 있어야 열리며 토큰이 비어 있으면 제공하지 않는다.
- 최초 메시지 인증, 5초 제한, 동일 세션 한 연결. 브라우저 Origin 정확 일치, 프록시 전달 IP를 맹신하지 않는다. IP당 업그레이드 30회/분, 전체 소켓 100개, 방 12개, 2인/방, 관전자 4명/방. 재접속 폭주 또는 같은 프록시 뒤 접속은 운영 환경에 맞게 조정해야 한다.
- 클라이언트 입력 상한 16KiB, 엄격한 명령 스키마, 초당 20개 제한, 40개 초과 연결 종료. 권한은 세션·방 구성원·방장·경기 상태로 검증한다. 클라이언트가 보낸 도시/자원/점수/랜덤 시드는 받지 않는다.
- 경기 ID, 행동 UUID와 단조 증가 sequence, 플레이어별 최근 승인/거절 256개 캐시. 재전송은 동일 응답, 다른 경기의 명령이나 오래된 sequence는 거절. 액션 접수는 단일 프로세스에서 순서대로 처리한다. 협동에서 충돌한 두 번째 요청은 자원과 블록을 유지한다.
- 서버 4Hz 시뮬레이션, 기본 2Hz 상태 전송. 액션/로비 변경 시 즉시 전송. 최상위 Game 필드 변경분과 revision/base를 전달하고 20회마다 전체 상태를 보낸다. 클라이언트가 revision을 놓치면 전체 재동기화를 요청한다. UI는 승인 전 도시를 변경하지 않고 배치 미리보기만 움직인다.
- 상대 도시와 관전자는 실제 공개 도시 상태만 수신한다. 양측의 미래 공급 RNG/전체 bag는 제거된다. 각 플레이어에게 자신의 현재 블록·다음 3개·보관만 전송한다. 관전자 hand는 null.
- 1MiB 미송신 버퍼를 넘긴 느린 소켓은 종료하고 재접속하게 한다. 10초 ping/pong으로 유령 연결을 정리한다. 명령 대기는 한 건으로 제한한다.
- 대전은 한 명이 끊겨도 진행한다. 60초 후 남은 플레이어 승리, 모두 끊겼으면 무효. 협동은 모두 끊겼을 때 정지하며 60초 이내 복귀하지 않으면 무효 종료한다. 경기 중 leave는 명시적 포기다. 이탈 유예를 넘어 영구 협동 저장을 제공하는 구현은 아니다.

## 데이터와 종료

SQLite 스키마 v1: `sessions`와 `matches`. 실행 중 경기를 DB에 먼저 생성하고 최종 결과는 `running=1` 조건으로 한 번만 확정한다. 프로세스 재시작 시 미완료 경기는 `serverRestart` 무효 결과로 확정한다. 정전 후 도시 중간 상태 복구·협동 영구 월드 저장은 지원하지 않는다. 브라우저 연결 복구와 서버 프로세스 복구를 구분한다.

DB 파일을 영구 볼륨에 두고 OS 권한을 서비스 계정으로 제한한다. 백업은 SQLite online backup 또는 프로세스를 중지한 상태에서 DB/WAL/SHM 일관성을 지키는 방식으로 한다. 실행 중 DB 단일 파일만 임의 복사하지 않는다. 결과와 게스트 세션에 대한 장기 보존/삭제 정책은 운영 전에 정한다. 만료된 세션은 시작 시 삭제한다.

## 배포

이 저장소는 정적 클라이언트와 장시간 실행되는 Node 서버를 별도로 빌드한다. 서버는 일반 단기 serverless HTTP 함수로 배포하지 않는다. 본 작업은 유료 서비스 생성, DNS, 인증서, 운영 라우팅 변경을 수행하지 않는다.

1. 영구 디스크가 있는 Node 24 컨테이너/VM에 `npm ci`, `npm run server:build`를 실행한다.
2. 서버 환경에 `NODE_ENV=production`, HTTPS `APP_ORIGIN` 또는 `APP_DOMAIN`, `DATABASE_PATH`, `HOST`, `PORT`를 설정한다. `APP_ORIGIN`이 있으면 우선한다. 별도 허용 출처는 `ALLOWED_ORIGINS`의 정확한 origin만 쓴다.
3. 클라이언트는 `npm run build` 결과 `dist`를 정적 호스팅한다. 같은 origin의 `/online`을 서버로 업그레이드 프록시하거나, 빌드 시 `VITE_MULTIPLAYER_URL`에 공개 WSS 주소를 설정한다.
4. TLS 종료 프록시의 WebSocket upgrade와 idle timeout을 설정한다. 외부에서 Node 포트에 직접 접근하지 않도록 네트워크를 제한한다. `HOST=0.0.0.0`은 컨테이너 내부 노출이 필요할 때만 사용한다.
5. supervisor/systemd/컨테이너 정책으로 재시작과 영구 볼륨을 유지한다. 서버 버전 교체는 진행 중 경기가 없는 시점에 한다. 강제 재시작은 무효 처리된다.
6. 외부 두 네트워크에서 WSS, 초대, 재접속, 결과 보존을 검증한 뒤 공개한다. 여기서 측정한 loopback 테스트를 인터넷 검증으로 간주하지 않는다.

현재 단일 프로세스 권위 서버이며 다중 인스턴스/Redis 라우팅/샤딩은 구현되지 않았다. sticky session만으로 확장 가능하다고 주장하지 않는다. 원시 세션 토큰·전체 도시 스냅샷은 접근 로그에 남기지 않는다. DDoS 보호, 계정 복구, 모더레이션, 신고 처리, 백업 복원 훈련은 공개 운영 전에 필요하다.

## 범위

우선순위 0–4의 단일 도시 대전·협동 기반에 빠른 매칭, 읽기 전용 관전, 게스트 전적을 더했다. 구조 공학 독립 경쟁, 제한 블록 퍼즐 경쟁, 별도 재난 생존 대회, 문명 레이스, 협동 월드/교역, 정식 계정, 랭킹/시즌, 리플레이는 제공하지 않는다. 재난 옵션은 두 도시에 동일한 바람 예보 일정을 적용하는 실제 기존 재난 규칙이다. 별도 순위 모드로 표시하지 않는다.

게스트 기록은 공식 랭킹이 아니다. 공개 출시/대규모 운영/하드웨어 GPU 성능은 별도 검증이 필요하다.
