# PHASE 11 — BALANCE & UX 개발 보고

## 1. Phase 1~10의 실제 구현 상태

3D 건축·순수 구조 판정·도시 운영·30개 캠페인·다층·재난·세계 운송·게스트 2인 온라인과 조작/시각 개선을 기반으로 한다. Phase 10은 핵심 아트 우선 구현이며 모든 에셋이 완성된 것은 아니다. PHASE10-REPORT.md의 범위를 유지한다.

## 2. 기존 밸런스 문제

100시드×1,000회 공급에서 필요한 플랫폼/도로/농장/전력/소형 부양기의 최대 재등장 간격이 44/46/44/49/45회였다. 긴급 조언도 3개에서 잘렸고, 구역이 분리된 식량 생산을 소진 예상에 합산했다. 창고가 가득 차도 식량 지원 비용을 지불할 수 있었다.

## 3. 중요도별 문제 분류

P1: 필수 공급 공백, 동시 치명 경고 누락, 구역별 식량 예측, 실효 없는 식량 지원 청구. P2: 긴 메뉴·좁은 자유 건설 버튼, 지원 제한 설명 부족, 인구 정체 설명과 큰 글자. 장시간 전략/경제 최적점은 추가 플레이테스트 대상이다.

## 4. 변경한 밸런스 데이터

BALANCE 메타데이터와 공급 이력24·필요 우선 시작8·연속 제한2를 중앙 rules.ts에 추가했다. 온라인 규칙 버전은2다. 전력 지원 비용을 중앙 상수로 옮겼다. 구조·생산·재난 피해 수치는 유지했다.

## 5. 건축물 능력치 조정

시설 ID·점유·질량·높이·전력·생산·노동·비용·유지비를 변경하지 않았다. 자동 도구가 기본 시설의 칸/질량/인력 대비 식량과 비용을 추출한다. 모든 시설이 동등한 효율을 가져야 한다고 가정하지 않으며 실제 가동/해금/형태 비용을 함께 봐야 한다.

## 6. 블록 공급 개선

신규 오프라인 v2는 필요한 해금 시설을 오래 기다린 순으로 우선 공급하고 반복2회를 제한한다. 도시 티어·세계 기술 잠금도 필터링한다. 고정 캠페인/훈련 스크립트와 온라인 공급은 보존한다. 기존 저장은 v1 경로로 이어간다.

## 7. 난이도 체계

기존 easy/normal/hard의 구조 강도·손상·유예·노동·소비·운영비·구호 차이를 유지했다. 프롬프트의 예시 숫자로 덮어쓰지 않았다. 정확한 값과 적용 경계는 DIFFICULTY_GUIDE.md에 있다.

## 8. 초기 사용자 경험

첫 10분에 실제 건축·연결·전력·주거 상황을 읽는 짧은 안내를 제공한다. 접기/다시 보기와 설정 해제가 가능하며 보상이나 해금을 잠그지 않는다. 처음 캠페인과 저장된 캠페인의 이어하기를 구별해 강조한다. 30초 시작/10분 성장 같은 인간 행동 목표는 아직 측정하지 않았다.

## 9. 인구 및 노동력

초기 보호 시간과 인구 정체/이주 원인을 도시 현황에 표시한다. 기존 구역별 인력·우선순위·부분 가동·유예 후 점진 이주는 유지한다. 인력 부족인데 생산하는 허용 규칙을 추가하지 않았다.

## 10. 전력과 식량

식량 소진은 주민이 있는 각 실제 도로 구역의 순소비로 계산하며 가장 먼저 부족해지는 시간을 표시한다. 양의 순생산은 무한대로 표시한다. 기존 연결 전력·유한 배터리·발전소 재시동 규칙은 유지하고 심각한 전력 부족 경고를 숨기지 않는다.

## 11. 경제와 자원 순환

긴급 식량은 전체 패키지를 받을 공간이 있을 때만 결제한다. 지원 버튼과 실행이 같은 적격성 검사를 쓴다. 유한 구호·쿨다운·수리/철거 비용·주문 지연·창고 소유 회계는 보존한다. 전역 세율이나 자원 종류를 추가하지 않았다.

## 12. 구조 안정성

전체 부양 부족과 국소 구조 위험을 구별하여 동시 표시한다. 코어 내구도25% 미만도 별도 최우선 경고다. 구조 해석·붕괴 순서·하중 전달은 렌더링 밖의 기존 순수 엔진을 유지한다.

## 13. 부양장치 밸런스

기본 코어500과 소형/대형 부양기의 출력·연료·전력·지연을 유지한다. 신규 적응 공급은 부양 부족 맥락에서 소형 부양기를 보장하지만 실제 배치 비용이나 전력 부족을 무시하지 않는다.

## 14. 수평·수직 건축

기존 보강·교량·계단·승강기·현수 구조와 층별 점유 규칙을 유지하고 회귀 검사한다. 같은 목표/자원으로 여섯 전략의 평균 효율을 최적화한 결과는 아직 없다. 설계 종류가 다른 진단 도시의 점수를 직접 공정성 순위로 사용하지 않는다.

## 15. 붕괴와 복구

실제 파괴와 주민 이재 상태를 유지한다. 코어·부양·응력 경고 위치 이동과 사용 가능한 지원/비용 설명을 개선했다. 자동 복구나 무한 무료 지원을 추가하지 않았다.

## 16. 재난 발생과 대응

기존 예보90·활동40·회복120초, 난이도/연구/미션 덮어쓰기를 보존한다. 활동 중인 재난은 치명적 도시 조언에 포함한다. 방어/무방어와 유예 종료 후 별도 자동 진단을 추가했다.

## 17. 기술 연구와 업그레이드

기존 실비 결제·선행 조건·가동 연구소·일회 완료·업그레이드 최대 레벨을 유지한다. 기준 runner의 잘못된 기술 ID로 시작 실패한 사례를 숨기지 않고, 실제 strongFrame 시작/완료를 별도 측정한다.

## 18. 탐험과 교역

기존 선박·항구·운송 중 재고·도착/창고 여유·연료·예비 재고 규칙을 유지한다. 수요 없는 자동 항로의 배송0과 실제 에테르 수요를 만든 배송 검사를 구분한다. 다중 도시 경고·잉여 조언은 Phase 9 구현을 보존한다.

## 19. 캠페인 스테이지별 조정

1–5 초보 건축, 6–10 도시, 11–15 공학, 16–20 수직, 21–25 재난, 26–30 세계 미션의 이름·필수/선택 목표·별·보상은 변경하지 않았다. 이번 수정은 UI·공통 지원 경계와 신규 일반 공급이다. 캠페인 스크립트는 고정이다.

## 20. 미션 달성 가능성

기존 전체 30개 미션의 실제 엔진 해법 테스트를 다시 실행한다. 검증 결과는 PLAYTEST_REPORT.md에 기록한다. 모든 미션의 모든 시드, 초보자 완주 시간 또는 무힌트 성공률을 주장하지 않는다.

## 21. 생존 모드

기존 1–10웨이브 성장 조건·유한 보상·예보·회복·방어 규칙을 유지한다. 메뉴에서 생존을 바로 선택할 수 있고 재난 실험실은 별도 그룹이다. 11웨이브 이후 수시간 인간 플레이는 미검증이다.

## 22. 온라인 경쟁

오프라인 적응 공급을 적용하지 않는다. 동일 시드/고정 맥락1000회 공급 동일성을 검사한다. 기존 정규화 가중치25/25/20/15/10/5와 목표 우선 동점 판정을 유지한다. 붕괴 승패는 서버가 생존 여부로 먼저 확정하므로 높은 도시 점수로 패배를 뒤집지 않는다.

## 23. 전략 다양성

같은 온라인 도시·재고·시드·60초 조건에서 여섯 단순 정책×3시드를 실제 권위 판정으로 실행했다. 단일 정책이 모든 시드에서 최고점은 아니었지만, 수직 전용 블록이 온라인 공급에 없어 vertical 정책은0배치였다. 여섯 인간 전략의 대전 승률은 미실시다. 이를 검증된 균형으로 오인하지 않도록 문서에 분리했다.

## 24. HUD와 UX

일반 조언은 최대3개, 동시 치명적 경고는 모두 표시한다. ID로 중복을 제거하고 일반 항목만30초 숨긴다. 실제 해소 시 사라진다. 인구 정체 이유·지원 불가 사유·메뉴 그룹·스크롤·넓은 프리셋 선택을 추가했다.

## 25. 접근성

글자100/115/130%, 높은 대비, 첫 안내 켜기를 추가하고 기존 모션·섬광·카메라·음량·키 반복 설정을 보존한다. 전 Canvas 확대나 모든 작은 장식 글자 확대, 임의 키 재배치는 제공하지 않는다.

## 26. 한국어와 영어

새 메뉴·안내·인구 원인·지원 제한·설정의 KO/EN 문자열을 제공한다. 1280×720에서 영어130%/고대비 자유 건설 버튼 폭과 페이지 넘침을 실제 브라우저로 검사했다. 전체 번역의 인간 감수는 미실시다.

## 27. 밸런스 자동 시뮬레이션

scripts/balance-audit.ts는 실제 tick/분석/재고/공급/점수 함수를 재사용한다. 100시드 공급과 기본15종×3시드, 추가 연구·배송·무방어·유예 종료 시나리오를 JSON/CSV로 기록한다. 초기 조건과 요청 시간/실제 진행 시간을 모두 기록한다.

## 28. 개선 전후 측정값

전후 원자료와 비교는 PLAYTEST_REPORT.md 및 docs/verification/phase11-before/after.json/csv에 있다. 기준 측정은 코드 변경 전에 실행했다. 초기 실패 설계/연구 미시작/배송0도 삭제하지 않았다.

## 29. 저장 데이터 보호

도시 v5와 기존 슬롯·별·세계·연구를 유지한다. 공급 v2/recent와 UX v1을 경계에서 검증하고 기존 저장에는 안전한 설정 기본값을 제공한다. 공급 버전 없는 저장은 기존 무작위 순서를 유지한다. 오류 시 저장을 덮어쓰지 않는 기존 경로를 보존한다.

## 30. 변경된 파일

rules·types·storage·supply·engine, city/report/actions/advisor/growth, FirstSteps/Interface/CampaignControls/DisasterUI/CityUI/PlayTools/App/style, 온라인 규칙 메타데이터, balance 단위/브라우저 테스트와 기존 메뉴 테스트, 개발 runner와 문서가 대상이다.

## 31. 자동 테스트 결과

최종 단위·타입·클라이언트·서버 빌드·포맷 결과는 PLAYTEST_REPORT.md에 기재한다. 테스트를 통과시키기 위해 게임 판정 조건을 완화하지 않는다.

## 32. 실제 브라우저 플레이

새 UX3흐름은 통과했다. 전체 Chrome과 Edge에서 캠페인·저장·자유·생존·그래픽·온라인 회귀를 확인한다. 실제 시각 자료는 docs/images에 보존한다. 최종 수량은 PLAYTEST_REPORT.md를 따른다.

## 33. 확인된 버그

긴급 식량 공간 미검사, 치명 경고 절단/무의미한 숨기기 버튼, 격리 식량 생산이 소진 시간을 덮는 문제, 좁은 자유 건설 버튼을 수정했다. Phase 10 CI의 벽시계 기반 소프트 드롭 검사는 시뮬레이션 시간 대비 가속을 확인하도록 고쳤다.

## 34. 미검증 항목

인간 재미·완주율, 여섯 전략 승률, 장시간 경제 최적점, 전 기기/보조 기기/임의 화면 배율, 실제 GPU와 WAN 장시간 검증은 미실시다. 자동 검사를 사람의 플레이 결과로 표현하지 않는다.

## 35. 남은 밸런스 문제

공급 보장은 지속적인 필요 맥락과 해금 조건에 한정된다. 기존 캠페인 무작위 후속 공급의 모든 장기 편차는 별도로 봐야 한다. 조언은 현재 문제와 일반 행동을 제시하며 자원별 최적 해결 위치를 완전 탐색하지 않는다. KNOWN_ISSUES.md 참조.

## 36. Phase 12 준비

재현 가능한 시나리오·버전 경계·전후 데이터·실패 조건·화면 증거를 남겼다. 다음 QA는 장시간 자원/저장/네트워크, 실제 GPU, 인간 초보·숙련 플레이와 동등 조건 전략 비교에 집중해야 한다. Phase 12/13을 구현하거나 출시했다고 주장하지 않는다.
