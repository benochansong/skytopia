# Phase 2 개발 완료 보고

SKYTOPIA: AETHER RISING — Gravity and Collapse. 작성일: 2026-11-26 (Asia/Seoul).

## 1. 기존 Phase 1 상태

기존 소스와 테스트에서 Three.js 공중섬, 16×16 논리 격자, 블록 회전/이동/보관/재활용, 20초 낙하, 도로 BFS, 발전·주거·인구 성장, First Light 미션, 행동 기반 훈련, v1 LocalStorage 저장을 확인했습니다. 기존 순수 로직 46개 및 Chrome/Edge 주요 흐름을 기준으로 회귀를 유지했습니다. 이전 검증 기록은 `VERIFICATION-PHASE1.md`에 보존했습니다.

## 2. 수정한 기존 기능

기존 엔진에 고정 시간 구조 시뮬레이션과 미션 유지 시간을 통합했습니다. 공급에는 새 종류와 제한된 수요 보정을 추가했고, v1 저장은 마이그레이션합니다. 도로 전력은 회로별 수요/공급으로 계산하여 분리된 구역의 자체 발전도 처리합니다. 코어 중심 부양과 섬 기반 질량을 포함하도록 이전 안정도 계산을 확장했습니다. 기울기/카메라 보간 중에는 클릭이 화면에 보이는 배치 예상 좌표를 확정하도록 수정했습니다. 포털 대화상자로 HUD 스크롤 영역에 확인 창이 잘리는 문제를 막았습니다.

## 3. 새 구조 기능

플랫폼 노드와 상하좌우 연결부, 시설별 질량/높이/내구성/전력 요구량, 연결부 손상/보강, 독립 부양장치, 분리 구역, 부양·균형·구조 점수와 독립 위험 판정을 구현했습니다. 배치 예측, 다섯 분석 오버레이, 위험 초점 이동, timed 수리, 단계별 보강, 비용/유효시간/재사용 제한이 있는 비상 부양, 철거 예측, 긴급 설계도, 원인별 패배 화면을 실제 상태 전이에 연결했습니다.

## 4. 무게중심·부양·기울기

시설 ID를 중복 집계하지 않고 블록 질량을 점유 칸에 균등 배분합니다. 플랫폼/보강재/섬 기반 80t까지 합산하며 `COM = Σ(m·position)/Σm`으로 XYZ를 구합니다. 시설의 Y는 정의된 높이의 절반을 사용합니다. 초기 총질량은 301t입니다.

유효 부양력은 코어 500t와 각 장치의 `최대 출력 × 내구성 비율 × 전력 상태 계수`, 비상 부양의 합입니다. 장치 계수는 정전 후 8초 유예, 초당 0.12 감쇠, 회복 시 초당 0.3 증가를 적용합니다. 연결된 장치는 20% 비상 출력을 유지할 수 있으며, 분리되어 전력이 없으면 0까지 감소합니다. 비활성화한 장치는 출력이 0입니다. 부양 중심은 실제 출력의 가중 평균입니다.

상승 가속 대신 정지 부양을 표현하기 위해 모멘트 계산의 총 작용 부양력은 `min(질량, 유효 부양력)`로 제한합니다. X/Z축 모멘트는 `L·COL.z − M·COM.z`, `M·COM.x − L·COL.x`이며 `atan(moment/4500)`를 ±25°로 제한합니다. 장면은 목표 기울기로 부드럽게 보간하고 논리 좌표는 회전하지 않습니다.

## 5. 하중 분산

살아 있는 플랫폼과 연결부의 그래프를 구성하고 코어에 연결된 초기 지반을 지지점으로 사용합니다. 독립 구역은 유효 부양장치 칸을 지지점으로 사용합니다. 장치 부양력은 실제 연결망을 따라 두 칸 안의 국소 하중을 먼저 줄입니다.

남은 하중은 지지점을 고정한 **그래프 라플라시안**을 결정론적 공액경사법으로 풉니다. 연결 강성은 동일하고 재료/내구성/보강은 허용 하중에 반영합니다. 모든 경로가 참여하므로 병렬 경로를 추가하면 하중이 분산됩니다. 연결부 전달량에는 지지점까지의 거리당 12% 모멘트 가중치를 적용합니다. 노드 하중은 자기 하중과 유입 하중의 합입니다. 해법은 최대 128회로 제한합니다.

종합 안정도는 부양 35%, 균형 30%, 구조 35%입니다. 부양 비율 80% 미만, 중심 거리 4.5 초과, 합성 기울기 22° 초과, 코어 손실은 평균 점수와 별도로 치명적 상태입니다. 일반 난이도에서는 20초의 대응 시간이 있습니다.

## 6. 손상·부분 붕괴·연쇄 붕괴

0.25초마다 `12 × max(0, 응력비−1)^1.5 × 난이도`의 초당 내구성 피해를 누적합니다. 시설도 지지 플랫폼이 심하게 과부하되면 피해를 입습니다. 내구성 감소는 허용 하중을 줄여 실제 악화를 유발합니다.

연결이 끊기면 컴포넌트를 다시 구분합니다. 코어 지지나 질량 이상의 자체 부양력을 갖추지 못한 구역, 내구성 0인 플랫폼을 큐에 넣고 한 단계에 최대 8칸 제거합니다. 여러 칸 건물은 지지 한 칸을 잃어도 ID당 한 번만 제거합니다. 인구·점유·질량·전력·수리 대상을 함께 갱신합니다. 발전소 손실은 살아남은 회로의 부양 출력 유예/감쇠로 이어지며 추가 위험은 다음 실제 계산에서 결정됩니다.

제거된 스냅샷은 사건 기록으로 남고 렌더러만 잔해를 표시합니다. 잔해는 최대 32개, 4초 뒤 사라집니다. 그동안 해당 플랫폼 좌표는 정리 중으로 표시합니다. 저장에는 이미 제거된 논리 상태가 들어가므로 로드 후 건물이 부활하지 않습니다.

## 8. 미션과 구조 실험

캠페인 02는 인구 50/안정도 75 등을 20초 유지합니다. 03은 편중된 산업 지구의 중심 거리 25% 감소와 안정도 80 회복을 10초 유지합니다. 04는 손상 구조 수리, 실제 연결부 2개 보강, 부양력 확보와 60초 생존을 요구합니다. 03/04는 초기 대응 준비 시간을 제공합니다.

A–D 실험은 무게중심·국소 부양·하중 경로·연쇄 붕괴의 독립 예제입니다. 모든 건물을 선택할 수 있고 시간 정지/재개/초기화와 별도 저장 슬롯을 제공합니다. 새 미션마다 법적으로 가능한 배치·복구 경로를 순수 엔진 테스트로 검증했습니다. 03의 검증 경로는 비용을 실제로 차감하는 긴급 설계도를 사용합니다.

## 9. 실행 방법

`npm ci` → `npm run dev` → 터미널의 로컬 주소를 엽니다. 프로덕션은 `npm run build`와 `npm run preview`를 사용합니다. 상세 환경/명령은 루트 README에 있습니다.

## 10. 주요 조작

WASD/방향키 이동, Q/E 회전, Space/클릭 배치, C 보관, X 재활용, 우클릭 드래그 회전, 휠 확대, H 시점 복귀, Esc 정지입니다. 분석 드롭다운/Tab으로 모드를 고르고, 구조물 선택 → 격자 → 수리/보강/철거를 사용합니다. 건물 아래 플랫폼과 주변 연결부는 선택 패널에서 전환합니다. 긴급 대응에는 비상 부양과 안전 건축물 구매가 있습니다.

## 12. 자동 테스트와 실제 브라우저 플레이

[검증 보고](VERIFICATION.md)에 최종 결과와 수행 범위를 기록했습니다. A–J 시나리오는 단위/브라우저 테스트에 대응합니다. 미션 완료 테스트는 엔진 시간 가속을 사용하며, 실험실 수리와 기존 자동 저장/낙하는 실제 브라우저 시간을 기다립니다. 수동으로 전체 캠페인을 무작위 공급만으로 완주했다고 주장하지 않습니다.

## 13. 성능 측정

동일한 256 플랫폼/255 시설 합성 도시로 계산 시간과 실제 WebGL draw call/frame time을 측정합니다. 캐시는 커서·카운트다운·인구 변경에서 구조 해석을 재사용합니다. 구조 상태 변경은 전체 그래프를 무효화하며 국소 증분 솔버는 아직 아닙니다. 반복 플랫폼·도로·정적 시설을 인스턴싱하고 기하/재질을 공유합니다. 애니메이션 부양 시설은 개별 모델을 유지합니다. 사건 48개·잔해 32개·손상 파편 표시 16구역으로 상한을 둡니다.

실측 수치, 실행 환경, 자원 해제 확인과 재현 명령은 [검증 보고](VERIFICATION.md)에 있습니다. 소프트웨어 WebGL 측정을 실제 GPU 성능으로 해석하지 않습니다.

## 14. 확인된 제한

정밀 유한요소 해석이나 다층 지지 계산을 하지 않습니다. 동일 연결 강성·거리 가중치·국소 부양 반경은 게임용 근사입니다. CG 반복 상한과 고정 스텝 작업 한도로 매우 복잡한 배치에서는 근사 오차가 생길 수 있습니다. 잔해끼리 충돌하거나 아래 구조물을 타격하지 않으며 자동 정리됩니다. 플랫폼/연결부는 직접 보강할 수 있으나 철거는 건물만 지원합니다. 코어 본체 내구성은 저장/시나리오·패배 판정에 사용하고, 일반 건설 손상은 코어 주변 플랫폼과 연결부에 적용합니다.

Firefox/Safari·모바일·장시간 메모리 프로파일링·실제 저사양 GPU FPS·수동 전체 캠페인 완주는 미검증입니다. Three.js 번들 크기 권고 경고가 남습니다. 무작위 공급의 모든 시드와 모든 난이도에서 동일한 미션 해결 시간을 보장하지 않습니다. 온라인 배포와 DNS는 변경하지 않았습니다.

## 15. Phase 3 준비

질량/부양/전력/하중/피해/복구/붕괴/렌더링 책임을 분리했고, 결정론적 시드·고정 스텝·버전 경계·사건 스냅샷과 회귀 테스트를 마련했습니다. 향후 경제·연구·다층 도시·외부 재난을 추가할 수 있습니다. 다층 도시에는 좌표/그래프/회전 관성/저장 버전 변경이 필요하며, 현재 y=0 제약을 그대로 확장할 수 있다고 가정하지 않습니다.
