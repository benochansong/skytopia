# Phase 3 — Living City 개발 보고

2026-11-26 (Asia/Seoul). 요구사항 원본: [PHASE3-SPEC.md](PHASE3-SPEC.md).

## 1. 기존 Phase 1·2 상태

Phase 2 커밋 `c86a9b3`를 기반으로 구현했습니다. 격자 배치·회전·보관·시드 공급·훈련·카메라, 하중 그래프·부분 붕괴·출력 유예·수리·보강·비상 부양·미션 1–4를 유지합니다. 이전 검증은 [별도 보존](VERIFICATION-PHASE2.md)했습니다.

## 2. 수정한 기존 기능

게임 버전을 3으로 올리고 순수 구조 계산에 시설 업그레이드와 실제 도시 전력 배분을 연결했습니다. 미션 1–4/훈련/구조 실험실은 기존 성장·대응 예산을 유지하고 미션 5부터 운영 규칙을 적용합니다. 낙하 블록은 여전히 일반 공급의 중심이며 주문은 지연된 큐 항목입니다. 새 운영 패널은 기존 구조 검사·배치 예측을 대체하지 않습니다.

## 3. 인구

주거 ID별 입주민, 총인구, 정원, 임시 거주, 입주/이주 누적을 분리했습니다. 주거 파괴 시 남은 연결 주거로 이동하고 자리가 없으면 30초 임시 거주 유예를 줍니다. 식량·전력·행복 위기는 각각 누적 시간을 사용합니다. 초반 보호 시간이 지난 뒤에도 한 번에 사라지지 않고 5초마다 일부 이주합니다. 완전히 비운 도시도 음식·연결 주거·안전이 회복되면 소수 개척민이 돌아올 수 있습니다.

## 4. 노동력·생산

일반 난이도의 노동 가능 비율은 60%입니다. 도로 구역별 인구에서 노동력을 계산하고 시설 우선순위/ID 순서로 배정합니다. 부분 인력은 부분 생산으로 이어집니다. 생산은 실제 인력, 전력 배분, 도로, 내구성, 행복, 에테르 투입, 저장 여유를 곱하며 재가동은 단계적으로 회복됩니다. 렌더링 프레임과 생산 계산은 분리됩니다.

## 5. 전력망

상하좌우 도로 연결은 기본 전력선을 겸합니다. 전력 연결재와 2칸 중계기는 전력망만 확장합니다. 플랫폼/연결부가 끊기면 해당 연결도 사라집니다. 별도 컴포넌트별로 발전·배터리·수요를 계산하여 다른 망의 발전량을 빌리지 않습니다. 부양, 의료, 주거, 농업, 산업, 상업 순으로 공급합니다. 발전소 자체는 전력을 요구하지 않아 재시동 순환 의존이 없습니다. 배터리는 기본 180에너지, 초당 15 충·방전 한도를 갖습니다.

## 6. 식량·저장

주민 한 명당 기본 초당 0.025식량을 소비합니다. 식량 생산과 같은 틱의 소비를 합산해 저장 상한을 넘지 않는 실제 처리량을 산출합니다. 식량 부족은 비축 소진 경고, 굶주림 시간, 행복 저하와 이주로 이어집니다. 저장은 코어/창고 시설의 개별 재고이며 도로망에 따라 접근을 묶습니다. 분리 시 재고 복제·이동이 없고 창고 파괴는 해당 재고를 손실시킵니다. 창고 정지는 물리적 용량과 기존 재고를 지우지 않습니다.

## 7. 경제

세금은 인구·행복·주거 전력에, 상업 수입은 인력·효율·수요에 따릅니다. 가동 시설은 유지비를 지출합니다. 크레딧과 건축 자재를 별도로 계산하고 모든 건설/수리/업그레이드 비용이 같은 재고를 사용합니다. 수입·지출·순수익은 분당으로, 생산·소비는 초당으로 표시합니다. 식량·자금이 감소하면 소진 예상 시간을 표시합니다. 일반 블록은 소액 크레딧, 긴급 건설은 자재와 크레딧, 고급 시설은 에테르도 요구합니다.

## 8. 행복·환경

기본값에 식량·전력·도로·고용·안전·최근 붕괴·주거, 근처 편의/소음을 합산합니다. 행복은 5초마다 최대 3포인트씩 목표에 접근합니다. 같은 물류 구역의 거리 4칸 이내 시설에 감쇠 영향도를 적용합니다. 공원/광장/병원/상업은 편의를, 산업은 소음을 제공합니다. 공원 편의는 소음을 완화하고 병원은 위기 이주량을 줄입니다.

## 9. 추가 건축물

19종을 추가해 총 32종입니다. 아파트·주거단지 / 고급 발전·에테르 발전·중계기·전력 연결재·배터리 / 온실·수경재배 / 작업장·고급 제조·정제소 / 기본 창고·물류 창고·곡물 창고·에테르 창고 / 광장·병원·상점. 모든 수치와 형태는 `src/data/rules.ts`에 있습니다. 기존 소형 주택·농장·공장·공원·부양 시설도 운영 규칙을 사용합니다.

## 10. 시민·차량

집계 인구와 분리한 대표 시민 최대 48명, 운송 차량 최대 16대를 인스턴싱합니다. 실제 도로 그래프의 집–일터/편의시설, 생산지–저장/주거 경로를 BFS로 만들어 캐시합니다. 끊어진 경로는 다시 계산하고 멈춘 시설은 경로 생성에서 제외합니다. 개별 주민의 직장 배정/소비를 시각 에이전트로 재현하는 구현은 아닙니다. 비행선은 외곽을 이동하는 환경 장식이며 교역 기능이 없습니다.

## 11. 낮·밤

하루는 시뮬레이션 시간 360초입니다. 하늘·안개·주광이 변하며 야간에도 구조를 식별할 수 있는 최소 조명을 유지합니다. 연결·전력이 있는 주거/발전 시설은 야간에 밝아집니다. City Lab에서 낮/밤을 바꾸고 설정에서 주기·환경·대표 시민·차량·그림자·움직임을 조절합니다. 시간 정지는 시민/차량의 이동과 하루 주기를 멈춥니다.

## 12. 업그레이드·도시 등급

업그레이드는 같은 점유를 유지하며 단계당 질량 20%, 주거 40%, 발전/생산 50%, 수요 30%, 부양 35% 등을 증가시킵니다. 시설별 추가 0–2단계 한도와 비용, 연결/전력, 예상 구조 위험을 검사합니다. 외형 높이도 바뀝니다. 인구 25/75/150/300/600과 자급·행복·안전 조건으로 6등급을 달성합니다. 600명/정원 648의 실제 16×16 배치로 자급·안정도 91.6·치명적 구조 위험 없음·70초 무붕괴·등급 보상 단발성을 검증했습니다.

## 13. 분석·조언

기존 구조 5개 분석에 전력선·식량 접근·주거 환경·물류 연결·운영 효율 표시를 추가했습니다. CITY ADVISOR는 구조/식량/전력 등의 우선순위로 최대 3개를 표시하고, 같은 문제는 하나로 합칩니다. 클릭 시 관리 창과 해당 위치로 안내하며 30초 숨기기를 지원합니다. 각 항목은 다음 행동을 한국어/영어로 설명합니다.

## 14. 미션 5–9

목표/문구/시작 공급/유지 시간은 데이터로 관리합니다. 정상 난이도의 순수 엔진 테스트는 각 미션을 140초 동안 진행하며 목표 동시 충족·유지·승리·일회성 보상을 확인합니다. 테스트는 알려진 공급 블록을 주입하지만 실제 배치 검증·비용·공급 전진·구조·경제 경로를 사용합니다. 따라서 임의의 모든 시드에 대한 승리 보증은 아닙니다.

| 미션                | 검증한 해결 경로                                                          |
| ------------------- | ------------------------------------------------------------------------- |
| 05 첫 번째 수확     | 연결 농장과 아파트 추가, 안정도/식량 유지하며 입주                        |
| 06 문명의 에너지    | 끊긴 발전 접속부 수리, 정지 시설 가동, 발전 추가 후 산업 회복             |
| 07 산업의 시대      | 인력·생산·흑자·과부하 없는 상태로 인구 100 이상 유지                      |
| 08 우리의 하늘 도시 | 국소 부양과 주거 주변 공원, 인구 150·행복 80·안정도 80                    |
| 09 침묵의 도시      | 발전/농업 재가동, 손상 플랫폼·연결부 수리, 국소 부양, 식량·행복·흑자 회복 |

City Lab A–E는 전력 정지, 식량 부족, 정상 산업, 손상 구조, 편의 정지의 실험 예제입니다. 별도 저장과 유한/무제한 전환을 지원합니다.

## 15. 구조와 경제의 연계

실제 전력 배분이 Phase 2 부양 출력에 입력됩니다. 건물 질량·높이와 부양 업그레이드는 구조 해석에 반영됩니다. 붕괴는 실제 시설/저장/주거/도로를 제거하고 생산·세금·접근·주민 이동을 바꿉니다. 코어 기본 부양은 자원 고갈에 종속되지 않습니다. 철거와 수리는 재고/크레딧을 사용하며 타이머와 구조 손상을 지우지 않습니다.

## 16. 저장 마이그레이션

캠페인 `skytopia.save.v3`, 구조 실험실 `skytopia.lab.v3`, 도시 실험실 `skytopia.city.v3`의 세 슬롯입니다. v1→v2 구조 변환 후 v2→v3 운영 필드를 명시적으로 추가합니다. 기존 미션에는 운영을 강제로 활성화하지 않습니다. 인구 회계·재고 용량/시설 소유·배터리·업그레이드·이벤트·주문 범위와 유한 수치를 검증합니다. 잘못된 최신 저장은 거부하며 이전 슬롯으로 조용히 되돌리지 않습니다.

## 18. 실행·조작

`npm ci` 후 `npm run dev`. [README](../README.md)에 전체 키보드/마우스 조작과 도시 운영 절차를 정리했습니다. 시설은 구조물 선택 또는 관리 창 시설 목록에서 선택합니다. 정지/우선순위/업그레이드는 시설 탭, 주문·구호·판매는 주문/지원 탭에 있습니다.

## 19. 자동 테스트

상세 결과와 실행 환경은 [검증 보고](VERIFICATION.md)에 기록합니다. 인구/인력, 기아 유예, 우선 전력, 배터리, 실제 생산, 유한 구호, 저장 손실, 주거 대피, 업그레이드, 시간/배속, 주문, 고립 창고, 난이도, 600명 수용, 미션 5–9와 기존 건설/구조 회귀를 포함합니다.

## 20. 실제 브라우저 플레이

Chrome/Edge에서 메뉴→도시 실험→시설 정지/재가동→업그레이드→주문→낮/밤→분석→배속/정지→저장→새로고침/불러오기 경로를 검증합니다. 기존 훈련·카메라·배치·붕괴·수리·승리·저장 실패도 회귀 범위입니다. 발견/수정 사항 및 최종 통과 수는 검증 보고에 구분합니다.

## 21. 성능

실제 600명, 256플랫폼, 135시설, 정원648의 자급 도시를 측정합니다. [CPU 원본](performance-city.json)과 검증 보고의 브라우저 측정은 환경·표본·중앙값/P95를 포함합니다. 네트워크·분석은 참조 캐시, 생산은 1초, 인구/행복은 5초, 구조는 0.25초, 반복 시설/시민/차량은 인스턴싱입니다. 소프트웨어 WebGL 수치를 일반 GPU의 FPS로 해석하지 않습니다.

## 22. 제한

집계 도시 운영과 대표 경로 연출입니다. 개별 주민 AI·교통 정체·운송 적재 지연·실시간 개별 물류 차량 회계는 없습니다. 도로 연결 구역 안에서는 재고를 즉시 공유합니다. 시설 모델은 코드로 만든 저폴리 모듈이며 여러 칸 시설은 반복 건축 모듈로 표시합니다. 사운드는 합성 효과음/화음이고 제공되지 않은 음악 파일을 구현했다고 주장하지 않습니다. 단일 높이 구조 근사, Firefox/Safari·모바일·실제 저사양 GPU·장시간 세션은 별도 검증이 필요합니다. Three.js 청크 크기 경고가 남습니다. 생산/소비 수치는 압축된 게임 시간 단위입니다.

## 23. Phase 4 준비

미션 ID별 시작 상태·공급·목표·유지 시간, 독립된 도시 명령/보고, 버전 저장, 구조/운영 이벤트가 캠페인 확장의 기반입니다. 다음 단계에서는 더 다양한 맵·사건·보상·목표 조합과 장기 밸런스 플레이 검증을 확장할 수 있습니다. 다층, 재해, 교역, 온라인 기능을 선행 구현하거나 완료로 표시하지 않았습니다.
