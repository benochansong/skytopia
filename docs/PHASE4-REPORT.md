# Phase 4 — Sky Campaign 개발 보고

2026-11-26 (Asia/Seoul). 요구사항: [PHASE4-SPEC.md](PHASE4-SPEC.md). 기반은 Phase 3 커밋 0427f32이며, 캠페인 핵심과 15미션의 실행 경로를 구현했습니다. 후순위 연출·튜토리얼·균형 조정의 남은 범위를 아래에 구분합니다.

## 1. 기존 Phase 1–3 구현 상태

격자·회전·낙하 공급·플랫폼·도로·전력·훈련·카메라, 질량/부양 중심·연결부 하중·내구도·붕괴·수리·보강·비상 부양, 인구·노동·전력망·식량·산업·경제·행복·업그레이드·낮밤을 기존 순수 TypeScript 엔진에서 재사용했습니다. 기존 103개 단위 테스트와 Chrome/Edge 20개 브라우저 흐름이 회귀 기준입니다. 이전 미완성 범위인 대표 시민/차량, 단일 높이, 즉시 구역 물류 등은 [Phase 3 검증](VERIFICATION-PHASE3.md)을 그대로 적용합니다.

## 2. 수정한 기존 기능

엔진에 선택적인 campaign 실행 상태를 추가하고 공급·배치·목표·종료를 캠페인 데이터에 연결했습니다. 기존 미션 승리 조건과 보상은 캠페인 실행 중 중복 적용하지 않습니다. 제한 퍼즐의 보관/주문 우회와 재활용 보너스를 차단했습니다. 도시 시나리오 생성기의 주거 종류를 선택할 수 있게 하되 기존 기본값을 보존했습니다. 도시 전력 자급은 전체 합계뿐 아니라 실제 개별 망의 부족량도 확인합니다.

메뉴/프로필/지도만 방문했을 때 예전 도시 슬롯을 저장하지 않도록 수정했습니다. 자유 건설 후 옛 저장 재개 시 저장 모드가 남지 않도록 초기화합니다. 3배속 미션 승리/실패 시 남은 누적 시간을 제거해 저장 스키마를 지킵니다. 손상된 캠페인 프로필은 자유 건설 저장이나 오프닝 재생으로 덮어쓰지 않습니다.

## 3. 캠페인 시스템

정의 → 초기 도시 생성 → 목표 평가 → 결과 → 프로필 갱신 → 검증 저장의 계층으로 분리했습니다. BUILD, EXPAND, BALANCE, REPAIR, OPTIMIZE, SURVIVE, PUZZLE, PRESERVE 유형을 실제 상태에 연결합니다. 목표는 AND/OR, 상한/하한, 일회성 달성, 연속 유지 시간을 표현합니다. 실패를 먼저 판정하고 결과를 한 번 확정합니다.

캠페인 지도에서 별·선행 해금·난이도·개인 기록을 확인하고 재도전합니다. 새 미션은 독립 도시이며 이전 공급·손상·주문·목표 타이머가 남지 않습니다. 완료 도시는 결과를 고정한 채 계속 건설할 수 있습니다. 실패 화면은 실제 실패 종류와 첫 구조 실패 기록을 보여주며, 재시도·체크포인트·훈련·지도 이동을 제공합니다.

## 4. 실제 플레이 가능한 챕터

1. 최초의 하늘: 연결, 거주, 확장, 농업, 자급 정착지.
2. 문명의 무게: 부양력, 균형, 병목 지지, 보호, 복구, 산업 안전.
3. 살아있는 문명: 재가동, 산업 효율, 삶의 질, 복합 위기, 250명 문명.

지도는 6개 지역을 표시하지만 챕터 4–6은 계획 상태로 비활성화했습니다. 미션 16–30의 명칭/챕터 데이터는 후속 작업용이며 플레이할 수 없습니다.

## 6. 스토리 및 등장인물

엘레나 보스(구조 기술자), 카엘 렌(에테르 과학자), 마야 솔렌(도시 운영), 오리온 베일(탐험)의 한국어/영어 이름·역할·색상·SVG 초상을 제공합니다. 미션마다 브리핑 두 줄, 다음/자동/건너뛰기, 읽은 기록, 대화 중 시간/입력 정지를 연결했습니다. 위기와 첫 목표는 중복 없는 기록 이벤트입니다. 미션 4의 생존자 8명 수용은 실제 인구·주거 부담을, 미션 11의 연구 지원은 60자재와 10에테르 교환 및 해당 미션의 에테르 발전소 시험 허용을 반영합니다. 선택은 저장되고 한 번만 실행됩니다.

오프닝은 5개의 자막을 9초씩 보여주는 45초 장면이며 기존 도시와 카메라 회전을 사용합니다. 설정에서 다시 볼 수 있습니다. 완료 시 실제 도시를 6초 보여주고 결과로 전환하며 건너뛸 수 있습니다. 미션 15는 오리온의 다음 여정 예고를 표시합니다. 전용 붕괴/지상 문명 영화, 성우 음성, 분기형 장편 대본은 구현하지 않았습니다.

## 7. 새로운 초기 공중섬

정사각, 길쭉한 섬, L자, 십자 확장, 동쪽 산업 편중, 좁은 목, 손상/외곽 손실, 기존 고밀도 도시, 13×13 최종 도시를 제공합니다. 미션 4의 전력망이 끊기지 않도록 십자 팔을 추가했고, 미션 5에 건축 여유 부지를 확보했습니다. 미션 15는 169플랫폼·76시설·인구 200에서 시작합니다. 플랫폼/건물의 실제 점유·하중·전력 상태로 구성하며, 예고용 다층/폭풍/다중 섬은 포함하지 않습니다.

## 8. 미션 평가 방식

필수 목표 전부 완료하면 별 1개, 첫 선택 목표 달성이면 2개, 두 선택 목표 모두면 3개입니다. 대다수 선택 목표는 안정도 90과 추가 붕괴 없음이며 첫 미션/균형 미션은 별도 조건입니다. 점수는 필수 3,000, 구조 최대 2,500, 연결 최대 1,000, 효율 최대 500, 선택 최대 500, 경제 최대 1,500, 생활 최대 1,000으로 계산합니다. 도시 운영이 꺼진 미션은 경제/생활 배점을 구조와 효율로 재배분합니다. 전문가 체크포인트 복원은 총점 10% 감점이며 결과에 기록합니다. 유형별 추가 가중치와 빠른 완주 보너스는 후속 조정 대상입니다.

## 9. 기술 및 건축물 해금

초기에는 플랫폼·집·도로·발전, 4부터 농장·창고·공원·대형 주거, 6부터 강화 플랫폼·보강재·소형 부양·균형추, 7부터 대형 부양, 10부터 산업과 시나리오 운영 시설, 11부터 고급 도시 시설을 허용합니다. 에테르 발전소는 11에서 연구 선택으로 시험하고 12부터 기본 허용합니다. 미션 5에는 소형 부양 시험 공급이 있습니다. 공급은 시작 순서 이후 허용 종류와 유효 형태에서 시드 난수로 선택합니다. 잠긴 시설의 배치·주문·긴급 설계도와 초반 업그레이드·수리/보강을 엔진에서 막습니다. 해금 프로필은 영구 기록이지만 과거 미션 재도전의 허용 시설은 해당 미션 규칙을 따릅니다. 별도 블록 형태/장식/스킨 해금 트리는 없습니다.

## 10. 건축가 성장 시스템

프로필 이름(최대 32자), 7등급(500 XP 간격), 총 플레이 시간·건설·확장·최고 인구/안정도·수리 통계를 저장합니다. 최초 완료는 미션 XP, 새 별은 25, 새 시설 종류는 10, 도전 과제는 40 XP입니다. 최고 별은 난이도를 가로질러 비교하여 난이도 전환이나 재시도로 경험치를 반복 획득하지 않습니다. 최초 완료/추가 별만 반영하고 최고/최근 점수는 별개입니다. 일일 도전은 별도 날짜 기록이며 XP는 없습니다.

## 11. 도전 과제

첫 건축, 25칸 확장, 100블록, 주거 연결, 균형, 연결부 보강, 구조 구출, 120초 안전, 첫 수확, 산업 생산, 60초 흑자, 행복한 주민, 3개 챕터 완료, 완벽한 챕터의 16개입니다. 실제 캠페인 상태를 보고 ISO 시각과 함께 한 번만 지급합니다. 자유 건설·실험실·완료 후 계속 건설은 캠페인 과제를 올리지 않습니다. 대부분은 현재 미션 조건이며 건축/확장 등 일부만 누적입니다.

## 12. 캠페인 저장 및 체크포인트

LocalStorage의 skytopia.campaign.v1에 버전 1 봉투로 프로필/현재 미션/단일 수동 체크포인트/자유 도시를 함께 저장합니다. 각 도시는 기존 v3 검증을 먼저 통과한 뒤 캠페인 상태를 검증합니다. 미션 ID·난이도·시드·대화·목표·자원·공급·평가·보상을 보존하며 파생 보고/장면은 다시 만듭니다. 체크포인트는 현재 실행의 미션·시드·난이도가 맞아야 복원합니다.

손상된 도시만 있으면 유효한 프로필을 보존하고 해당 스냅샷을 제외합니다. 프로필이 손상되면 원문을 유지하고 경고하며 명시적인 새 캠페인 시작으로만 초기화합니다. 저장소 비활성/용량 초과도 성공으로 처리하지 않습니다. 기존 v1/v2/v3 도시 마이그레이션은 유지합니다. 새 봉투가 없으면 기존 저장에서 확인 가능한 승리만 대응 캠페인 별 1개로 가져오고, 미완료 도시는 원래 슬롯에서 이어합니다. 일일 기록 포함 최대 300개 검증 한도가 있어 장기간 일일 기록 보존 정책은 후속 작업입니다.

## 13. 자유 건설과 실험 모드

기존 미션·훈련·구조 실험실 A–D·도시 실험실 A–E와 세 저장 슬롯을 유지했습니다. 새 자유 건설은 도시 실험실 C의 기반 도시와 공통 관리 도구를 사용하되 유한 자원으로 시작하며 별도 자유 슬롯에 저장합니다. 예제 변경/무제한 도구도 공통 실험 UI에 남아 있어 엄격한 경쟁용 샌드박스가 아닙니다. 캠페인 진행과 보상은 분리됩니다.

## 15. 게임 실행 방법

Node.js 22.12 이상에서 npm ci 후 npm run dev. 터미널의 로컬 주소(기본 127.0.0.1:5173)를 엽니다. npm run build는 dist 정적 빌드, npm run preview는 빌드 확인입니다. Chrome/Edge WebGL이 필요하며 API 키·백엔드는 없습니다. 도메인/DNS/공개 배포를 변경하지 않았습니다. 절대 URL을 도입할 때 중앙 APP_DOMAIN/APP_ORIGIN 설정을 사용합니다.

## 16. 주요 조작 방법

WASD/방향키 이동, Q/E 회전, Space/왼쪽 클릭 배치, C 보관, X 재활용, 오른쪽 드래그 회전, 휠 확대, 가운데 드래그 이동, H 시점 복귀. Esc 일시정지, 체크포인트 버튼 저장, 기록·지도에서 복원/지도 이동. 도시 운영 버튼은 시설·주문·생산·경제, 구조 패널은 선택·수리·보강·분석입니다. 첫 미션은 낙하/붕괴를 끄고 고정 공급·힌트를 제공하며, 기존 단계별 카메라/배치 훈련도 메뉴에 유지합니다.

## 17. 자동 테스트 결과

최종 단위 테스트 137개(기존 103 + 캠페인 34)가 통과했습니다. 15 본편 + 3 도전의 실제 엔진 승리 경로, 스키마·세 난이도 시작 상태·대화 정지·보상 중복·최고 기록·선택 효과·실패 우선·체크포인트·구버전 이관·3배속 종료 저장을 확인합니다. TypeScript strict와 프로덕션 빌드도 통과했습니다. 브라우저/형식/최종 측정의 정확한 실행 결과는 [VERIFICATION.md](VERIFICATION.md)에 기록합니다.

## 18. 실제 플레이 검증 결과

Chrome/Edge에서 새 프로필 → 오프닝 건너뛰기 → 대화 중 정지 → 5개 실제 Space 배치 → 결과/별 → 다음 미션 → 체크포인트 → 지도 → 새로고침/이어하기를 자동 조작했습니다. 커서는 테스트 연결로 지정하고 인구 성장 시간은 가속하므로 사람의 전체 플레이 기록과 다릅니다. 지도 잠금·프로필·도전·언어 전환·자유 저장 분리·손상 저장 보호도 브라우저 검증 대상입니다. 본편 2–15는 순수 엔진 해법으로 검증했으며 사람이 전 미션을 처음부터 끝까지 완주했다고 주장하지 않습니다.

## 19. 미션별 확인된 밸런스 문제

미션 4의 초기 십자 구성에서 전력 연결이 끊기는 문제를 수정했습니다. 미션 5의 주거·농업 공간 부족을 추가 부지로 해결했습니다. 미션 7–9는 외곽 부양과 병목 보강이 핵심이며 단순 인구 추가로 해결되지 않습니다. 미션 10–14의 준비 도시가 충분히 크므로 숙련 해법은 짧게 끝납니다. 미션 13은 다수 공원/주거 여유를 요구합니다. 미션 15의 초기 해법은 외곽 하중이 무너졌으며, 목표 안정도 85를 낮추지 않고 실제 보강과 추가 부양을 포함해 성공시켰습니다.

현재 일반 난이도에서 필수 목표 완주를 확인했습니다. 선택 안정도 90 때문에 미션 5/7/10–15 해법은 1별이며 모든 미션의 3별 경로는 검증하지 않았습니다. 무작위 블록의 장시간 분포, 스토리/전문가 전체 완주, 초보자의 5–25분 체감 길이·실패율·학습 부담은 별도 플레이 세션으로 조정해야 합니다.

## 20. 성능 및 최적화

캠페인 UI와 Three.js 장면을 지연 로드하고 지도/프로필/도전 화면에서는 Canvas를 제거합니다. 단일 Runtime 시계와 정리 가능한 대화/연출 타이머를 사용합니다. 챕터별 하늘/암석 색과 합성 음악을 적용하고 기존 인스턴싱·보고 캐시·환경 옵션을 유지합니다. 최종 도시 CPU 0.25초 처리 중앙값 10.808ms, 초기 생성 535.030ms를 측정했습니다. SwiftShader의 최종 완료 도시 평균은 2.83 FPS로 느리며 실제 GPU에서는 별도 측정이 필요합니다. 캠페인 WebGL 측정 1개가 통과했고 첫 장면 재입장 geometry는 129→131→129였습니다. CPU 및 소프트웨어 WebGL의 실제 수치는 [검증 보고](VERIFICATION.md)와 performance-campaign JSON에 기록합니다. 반복 입장 테스트는 짧은 3회이며 장기 메모리 누수 부재의 증명은 아닙니다.

## 21. 아직 구현하지 못한 기능

후순위 범위: 전용 5장면 영화, 세밀한 챕터 지형/식생/안개/입자 프리셋, 성우/음성 볼륨, 완전한 음악 트랙, 미션별 다단계 행동 감지 튜토리얼, 상황별 다중 대화/분기, 스킨·장식·블록 형태별 보상 트리, 유형별 점수 가중치, 모든 미션의 3별·모든 난이도 균형 검증입니다. 시스템 활성화는 낙하/구조/도시 운영의 묶음 단위이며 모든 하위 경제 기능을 독립적으로 단계 해금하지 않습니다.

## 22. 알려진 버그 및 제한 사항

Three.js 청크 크기 권고 경고가 남습니다. 실제 GPU/저사양/모바일/Firefox/Safari/장시간 세션은 미검증입니다. SwiftShader 측정은 실제 GPU 성능이 아닙니다. 한 브라우저/origin의 로컬 저장이며 계정 동기화·서버 기록·치트 방지는 없습니다. 제한 퍼즐은 6개 고정 순서를 보호하려고 보관/주문을 끕니다. 대체 지지 경로 목표는 미션 8의 지정 병목 좌표에 특화되어 있습니다. 새로운 실패 원인을 추정해 실제 사건처럼 표시하지 않으며, 일반적인 복구 제안은 제안으로 구분합니다.

## 23. Phase 5 개발 준비 상태

챕터/미션 데이터, 목표 평가, 공급 정책, 진행 저장, 잠금 지도에 챕터 4를 연결할 수 있습니다. 하지만 높이 좌표·수직 점유·기둥/교량 하중·카메라 층 선택·저장 마이그레이션은 새 설계가 필요합니다. 이를 단순히 지도 잠금 해제로 활성화하지 않아야 합니다. Phase 5 시작 전 실제 다층 구조 엔진과 충돌/붕괴/저장 테스트를 먼저 추가하고 미션 16–20을 검증해야 합니다.
