# Phase 5 — Vertical Civilization 구현 보고

검증일: 2026-11-26, Asia/Seoul. Phase 4 브랜치 위에서 실제 게임 엔진·화면·저장·캠페인을 확장했다. 핵심 플레이는 구현했으며, 아래 제한 사항을 포함해 원문 기획의 모든 세부 연출을 완료한 상태는 아니다.

## 1. 기존 Phase 1–4 상태

낙하 블록 공급·회전·보관·재활용, 구조 하중·붕괴·복구, 도시 인구·식량·전력·행복·경제, 15개 캠페인과 3개 도전의 기존 코드를 유지했다. 0층 좌표 ID와 기존 저장 원문을 보존한다. 이전 검증은 `VERIFICATION-PHASE4.md`에 남겼다.

## 2. 수정한 기존 기능

도로/전력 계산에 층 정보를 넣었다. 실제 전력이 없는 승강기를 이동 그래프에서 제외하고 전력 복구 시 다시 연결한다. 부재 연결부의 수리·보강은 해당 부재에 적용하며 잘못된 수직 타일 간선 저장을 만들지 않는다. 구조 이벤트·긴급 부양 좌표에서 층을 보존하고 부가 플랫폼 속성을 제거한다. 숨긴 시설의 바닥 클릭 선택도 차단한다.

## 3. 3차원 격자

논리 좌표는 X/Y/Z, Y 범위는 -2…+4다. `VERTICAL.height=3`이 화면 높이의 기준이다. 기존 0층 키 `x,z`는 그대로이며 다른 층은 `x,y,z`다. 논리 충돌·연결·질량 계산은 React/Three.js와 독립된 TypeScript 모듈에 있다.

## 4. 저장 마이그레이션

도시 스냅샷 v3→v4, 캠페인 봉투 v1→v2로 올렸다. 새 키가 없을 때 이전 키를 읽고 새 키에 저장하므로 이전 원문이 남는다. 프로필 버전은 유지하며 이름·XP·별·최고/최근 기록을 보존한다. 수직 실험실은 `skytopia.vertical.v1`에 따로 저장한다. 좌표, 체적 중복, 부재 시작점, 회전, 인구 회계, 재고를 검증하며 손상 데이터는 거절한다.

## 5. 상층·하층 플랫폼

일반/강화/정원/현수 데크를 추가했다. 상층 데크에는 실제 연결된 지지 경로와 제한된 외팔 거리가 필요하다. 하층 중앙 암석 체적과 겹치는 배치는 거절한다. 데크 자체의 질량·내구도·하중 한계가 계산에 들어간다.

## 6. 신규 입체 블록

수직 I, 입체 L, 계단형, 3D 모서리, 아치, 쌍기둥, 현수, 교량 스팬, 다층 데크 형태를 추가했다. 복합 데크는 각 층에 지지가 있어야 배치된다. 모든 블록은 Y축 회전, 보/트러스만 X/Z축 회전을 허용한다. 주거 타워는 두 층의 체적을 차지한다.

## 7. 기둥·구조 보

기본/강화/산업/에테르 기둥, 보, 트러스, 대각재, 현수재를 추가했다. 쌍기둥은 두 지지 경로에 질량과 용량을 나눈다. 인접 대각재는 좌굴 저항을 보완한다. 기둥 연속 높이와 손상이 실제 허용 하중에 영향을 준다.

## 8. 수직 하중

수평 플랫폼 그래프에 실제 부재 끝점을 연결하고 기존의 반복 횟수가 제한된 하중 솔버를 사용한다. 여러 기둥은 하중을 분담하고 한 경로가 사라지면 재계산한다. 부재 질량을 중복 계상하지 않는다. 압축과 현수 인장 용량은 별도 데이터다.

## 9. 3차원 무게중심

플랫폼 높이, 시설 높이, 부재 끝점과 보강 질량을 포함해 X/Y/Z 중심을 계산한다. 부양 중심에도 Y를 포함한다. 높은 무게중심은 기존 회전 강성에 영향을 주고 하부 산업 질량은 중심을 낮춘다. 이는 게임용 근사 모델이며 실제 건축 안전 해석 도구는 아니다.

## 10. 수직 붕괴·복구

과부하로 플랫폼·부재가 손상되고, 마지막 지지 경로를 잃은 구역이 제한된 큐를 통해 붕괴한다. 연결 교량·승강기·시설도 제거되어 교통과 전력이 끊긴다. 낙하 충격은 같은 X/Z의 가장 가까운 하부 데크에 상한을 둬 적용한다. 수리·영구 보강·철거·긴급 부양과 20초 임시 부재 보강/45초 재사용 대기가 있다.

## 11. 공중 교량

보행/도로/강화/아치/현수/에테르 교량을 추가했다. 두 끝 플랫폼과 중간 공간을 검사하며 실제 구조·보행·전력 간선을 연결한다. 화물·차량 허용 종류를 구분하고, 에테르 교량은 정전 시 통행이 중지되고 구조 용량도 줄어든다. 현재 교량 스팬은 3칸이다.

## 12. 계단·승강기

계단, 승객/화물/에테르 승강기를 구현했다. 승강기 전원 부족은 실제 이동 연결을 끊고 대체 계단이 있으면 보행이 유지된다. 표시되는 승강기 칸도 전원 상태를 따른다. 개별 승객 대기열·엘리베이터 배차는 아직 없다.

## 13. 다층 도로·전력

보행, 화물, 차량, 전력을 각각 계산한다. 차량은 계단을 지나는 경로를 사용하지 않는다. 승강기 전력 단자는 각 층에서 전기를 분배하지만 층간 송전은 별도 중계기가 담당한다. 화물 연결이 없는 비지상 생산에는 35% 운반 계수를 적용한다. 개별 화물량과 승강기 처리량을 시간별로 예약하는 물류 모델은 미구현이다.

## 14. 하부 산업

암석 밖의 현수 데크에 공장·부양 장치·수직 전력·화물 승강기를 연결할 수 있다. 생산량, 전력, 노동력, 질량, 도로 단절이 기존 도시 경제와 함께 작동한다. 아래쪽 배송은 드론 접근으로 취급한다.

## 15. 층별 보기·단면

전체, 선택 층 이하, 대각 단면, 구조, 하부, 설계도 보기를 제공한다. 숨김은 계산 상태를 바꾸지 않는다. 자유/평면/정면/측면/하부/현재 층 카메라를 제공하며 섬 기울기를 반영한 배치 평면을 사용한다. 단면은 층과 사분면 기준의 객체 숨김이며 임의 절단면으로 메시를 자르는 기능은 아니다.

## 16. 구조 분석·설계도

기존 하중·내구도·연결·부양 분석을 실제 층 높이에 표시한다. 공방에는 층별 데크 수·자체 질량·위험 지점, 무게중심·부양 중심 높이, 선택 부재 하중/용량을 표시한다. 구조 보기는 시설을 숨기고, 설계도 보기는 데크 와이어와 구조 연결을 표시한다. 차기 공급 미리보기는 평면 아이콘과 Y 범위를 병기한다.

## 17. Chapter 4 실제 미션

## 21. 실행

Node 22.12 이상에서 `npm ci`, `npm run dev`. 검증은 `npm test`, `npm run build`, `npm run test:e2e`, `npm run test:e2e:edge`. 공개 배포·DNS 변경은 수행하지 않았다.

## 22. 조작

층 버튼 또는 PgUp/PgDn으로 층을 바꾼다. Q/E는 Y축 회전, R/F는 보·트러스의 X/Z축 회전이다. WASD/방향키, SPACE 배치, C 보관, X 재활용은 유지한다. 공방에서 구조재 설계도·시설 주문·보기·카메라를 사용한다. 미션의 설계도는 비용을 내며 주거·정원 등은 무작위 공급 또는 주문으로 받는다.

## 23. 자동 테스트

최종 결과는 `VERIFICATION.md`에 기록한다. 0층 호환성, 세 축 회전·체적 충돌, 하중 분산·좌굴·붕괴·임시 보강 만료, 승강기 정전과 대체 계단, 교량 단절, 하부 인장, v3/v1 원문 보존과 v4 저장, 캠페인 1–20 승리 경로를 포함한다.

## 24. 브라우저 플레이 검증

Playwright가 설치된 실제 Chrome/Edge를 조작한다. 사람의 전 캠페인 완주와 구분한다. 상층 주거 직접 건설, 층 전환, 공방, 별도 저장·재개, 실험실 예제, 보기·카메라, 기존 회귀 흐름을 검증한다. 캡처와 실행 결과는 `VERIFICATION.md`에 기록한다.

## 25. 성능

`performance-vertical.json`은 Ryzen AI 9 365/Node 24의 CPU 실측이다. 초기 대도시 187데크·126시설, 4층 합성 부하 256데크·252시설을 사용했다. WebGL 측정은 SwiftShader 소프트웨어 렌더링이며 실제 GPU FPS로 해석하지 않는다. 자세한 표와 표본 수는 검증 문서와 JSON을 참조한다.

## 26. 확인된 문제

수직 패널을 알림이 가리던 클릭 방해, 예제의 시설/기둥 중복, 가변 배열로 인한 연결 캐시 오염, 승강기 단자 전력 연결, 부재 간선 보강 저장 문제를 수정했다. Three.js 청크 크기 경고와 소프트웨어 렌더링 성능 한계가 남는다. 모든 조합·시드·장시간 플레이를 검증한 것은 아니다.

## 27. 미완성·제한

교량 가변 길이, 개별 차량/화물 적재·용량 예약, 정교한 엘리베이터 배차, 임의 메시 단면, 드래그 영역 선택, 세밀한 구조 전용 음향·시네마틱은 후속 작업이다. 구조·설계도 모드는 시설 모델을 숨기는 분석 모드다. 물리 모델은 격자와 제한된 그래프 솔버 기반이며 실제 연속체/재료역학 해석은 아니다. 난이도별 시작 저장은 검증했지만 모든 난이도·모든 3별 경로를 완주 검증하지 않았다.

## 28. Phase 6 준비

층별 질량·지지·전력·교통 그래프, 손상·붕괴 이벤트, 복구 액션과 버전 저장 경계가 마련됐다. 바람·운석·예보·재난 대응 정책·Chapter 5는 아직 구현하지 않았다. 재난별 힘/손상 입력과 회복 경로를 이 엔진에 추가할 수 있다.
