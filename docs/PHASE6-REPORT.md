# Phase 6 — STORMS OF AETHER 완료 보고

검증일: 2026-11-26 (Asia/Seoul). 원본 요구사항은 [PHASE6-SPEC.md](PHASE6-SPEC.md), 검증 근거는 [VERIFICATION.md](VERIFICATION.md)입니다.

## 1. 기존 Phase 1–5

낙하 블록·회전·보관·공급·구조 하중·붕괴·경제·인구·행복·캠페인 1–20·수직 건설을 유지합니다. 5단계는 별도 PR4에 보존했습니다. 이전 기능의 상세 제한은 [5단계 보고](PHASE5-REPORT.md)를 따릅니다.

## 2. 수정한 기존 기능

저장 버전을 5로 올리고 비상 배터리를 기존 전력망의 유한 충·방전에 통합했습니다. 캠페인 난수 시드의 허용 범위를 uint32로 바로잡았습니다. 3D 표시의 구조 계산에도 재난 상태를 전달하며, 생존 모드의 재활용은 일반 공급 큐를 진행합니다.

## 3. 기상

맑음·구름·산들바람·비·안개와 강풍·뇌우·한파·고온·에테르 기상을 지원합니다. 풍속·온도·구름·비는 게임 시각으로 완만하게 바뀝니다. 이전 미션에는 재난 상태를 생성하지 않습니다.

## 4. 예보

시드와 고유 ID로 종류·등급·방향·위치·발생 시각을 미리 확정합니다. 기본 준비 시간은 90초, 실제 재난은 40초입니다. 관측소는 충돌 개수, 관측탑은 정밀 시각을 제공합니다. 관측시설이 없어도 위험 구역 경고가 있습니다.

## 5. 공중 폭풍

풍속의 제곱, 시설 면적·높이·고도에 따른 횡하중과 토크를 적용합니다. 비 입자·하늘색·안개·합성 경보가 실제 재난 시각을 사용합니다.

## 6. 풍하중과 구조

실제 질량은 유지하고 추가 등가 하중을 구조 그래프에 분배합니다. 상류 시설과 방향성 방풍벽은 노출을 감소시킵니다. 유체역학이나 유한요소 해석이 아닌 게임용 근사 모델입니다.

## 7. 낙뢰

높은 시설을 가중한 결정적 표적을 사용합니다. 실제 내구성과 발전 출력에 영향을 주며, 피뢰침은 충격을 유도하고 서지 시설은 정전 시간을 줄입니다. 정전은 기존 전력·배터리·부양 감쇠로 이어집니다.

## 8. 운석

예고된 위치와 시각에 유한 반경 피해를 줍니다. 시설·데크·기록된 연결부에 실제 손상을 반영하며, 충돌 ID로 저장 후 중복 타격을 방지합니다. 코어 데크의 즉각 소멸은 제한합니다.

## 9. 방어막

소형 반경 3·용량 90, 대형 반경 5·용량 220입니다. 실제 전력·인력과 에테르를 사용해 초당 3 충전하며, 흡수한 양을 차감합니다. 가장 충전된 유효 방어막 하나가 처리하고 초과 피해는 전달됩니다.

## 10. 에테르와 온도

에테르 폭풍은 거리·강도·시간에 따라 부양 출력을 일시 감소시킵니다. 안정화탑이 감소를 완화합니다. 중력 이상은 국소 구조 하중에 적용합니다. 한파는 주거 수요, 고온은 산업 수요를 높이고 노출 농업 생산을 줄입니다.

## 11. 신규 시설

기상 관측소·관측탑, 방풍벽·강화 방풍벽, 피뢰침·피뢰탑·서지 보호기, 소형·대형 방어막, 안정화탑, 비상 배터리·식량창고, 대피소, 복구센터, 기후 제어기 15종입니다. 질량·비용·수요·능력치는 rules.ts에 모았습니다.

## 12. 비상 정책

정상·전력·절약·방어·대피·복구의 단일 정책을 선택합니다. 전력·절약·대피는 산업·상업 가동률을 35%로 낮추며, 방어·복구는 해당 시설의 전력 우선순위를 높입니다. 비상 전력과 주문은 비용·시간 제한을 유지합니다.

## 13. 주민 대피

실제 도로·가동 중인 승강기로 연결된 대피소만 이용합니다. 시설당 80명 한도이며, 주거 인구를 대피 명부로 옮겨 전체 인구 회계를 유지합니다. 대피 인구는 일하지 않고 식량을 소비하며, 종료 후 연결 가능한 주거로 복귀합니다.

## 14. 피해 처리

재난 전후 인구·안정도·시설·부양·전력·식량·재고·회복력을 기록합니다. 피해 시설, 무너진 데크, 흡수량, 대피, 수리 비용을 보고합니다. 효과 24개, 충돌 계획 8개, 보고 20개, 재건 설계도 256개로 제한합니다.

## 15. 복구와 드론

가동 복구센터는 반경 5 안에서 4초마다 실제 비용을 지불해 최대 3개의 수리 작업을 예약합니다. 코어 데크·지지·부양·발전·교통을 우선하며 수리 드론은 실제 작업을 표현합니다. 잃어버린 구조물은 기존 비용·지지·충돌 규칙으로 재건합니다.

## 16. 회복력

지지재, 여유 부양력, 분산 발전, 유한 배터리, 식량, 방어막 범위, 대피소, 수리 시설을 합산한 0–100 지표입니다. 지지 항목은 지지재 수를 사용하는 근사치이며 모든 대체 경로의 독립성을 증명하는 수치는 아닙니다.

## 17. Chapter 5

21 폭풍 준비, 22 운석 방어, 23 에테르 위기, 24 유료 수리·끊긴 교량 재건·주민 복귀, 25 300명 복합 위기입니다. 모든 미션을 비용을 지불한 배치와 실제 시간 진행으로 승리하고 저장할 수 있음을 자동 해법으로 확인했습니다. 모든 공급 시드·난이도 3별 해법을 보증하지 않습니다.

## 18. 생존 모드

10종 순서의 반복 웨이브와 최대 5등급 상승, 회복 시간, 3종 보상, 성장 조건, 중복 보상 방지, 로컬 최고 기록을 제공합니다. 인구 조건은 130명에서 시작해 웨이브마다 10명씩 증가하고 240명에서 멈춥니다. 10웨이브 자동 검사는 스케줄러·저장·보상 경계를 분리 검증하며, 장기 도시 생존 밸런스를 증명하는 플레이 검사는 아닙니다.

## 19. DISASTER LAB

A 강풍, B 방풍, C 낙뢰, D 운석, E 에테르, F 복합 위기를 제공합니다. 종류·등급·방향·풍속·지속 시간·커서 표적·방어 사용을 설정합니다. 정지 상태로 시작하며 실행·배속은 기존 도시 시간 제어를 사용합니다. 실험실은 캠페인 보상을 지급하지 않습니다.

## 20. 저장 마이그레이션

도시 v5, 캠페인 봉투 v3, 수직 실험 v2를 사용합니다. 재난 실험과 생존은 각각 별도 v1 키에 도시 v5를 저장합니다. 이전 v1–v4 및 캠페인 v1–v2 원문을 덮어쓰지 않고 읽어 이행합니다. 예보·충돌·방어막·정전·대피·복구·웨이브를 검증하며 손상 데이터는 거부합니다.

## 21. 변경 파일

새 규칙은 types/disaster.ts와 game/disasters의 state·scheduler·effects·protection·evacuation·recovery·manager·report·schema·scenarios·survival에 있습니다. UI는 DisasterUI, DefenseFacility, DisasterEffects에 추가했습니다. 기존 engine·city·stability·storage·campaign·store·scene를 연결했고 테스트, 성능 스크립트, README와 검증 문서를 갱신했습니다.

## 22. 실행

Node.js 22.12 이상에서 npm ci, npm run dev. npm test, npm run typecheck, npm run build, npm run test:e2e, npm run test:e2e:edge로 검증합니다. 외부 서버·API 키·유료 에셋은 필요 없습니다.

## 23. 조작

메뉴의 재난 실험실·생존 모드에서 시작합니다. 중앙 기상 패널의 재난 대응으로 정책·방어 주문·예보·분석·복구를 조작합니다. 8종 분석 보기와 입자·번쩍임 감소·화면 흔들림·경보 음량·아이콘 크기를 설정합니다. 자유 건설에서는 재난 없음이 기본이며 직접 켤 수 있습니다.

## 24. 자동 테스트

최종 수치와 명령은 VERIFICATION.md에 기록합니다. 기존 단계 회귀, 25개 미션의 모든 난이도 초기 저장, 실제 21–25 승리, 결정적 예보, 중복 충돌·보상, 전력 연계, 인구 회계, 수리 비용을 검사합니다.

## 25. 브라우저

Chrome에서 실제 버튼으로 재난 예보·분석·저장·재개·피해 보고와 A–F 예제를 검증합니다. 결과·스크린샷·실패 후 수정 내역은 VERIFICATION.md에 기록합니다.

## 26. 밸런스

초기 중형 도시는 분산 소형 부양기와 지지 연결부를 조정해 예보 전 자발적 붕괴를 제거했습니다. 소형 방어막은 반경이 좁아 배치가 중요하며 운석 미션의 검증 해법은 대형 방어막을 사용합니다. 수리·방어·정전·유한 배터리의 실제 차이를 확인합니다.

## 27. 성능

CPU 계산과 소프트웨어 WebGL 수치를 분리 기록합니다. 공간 키 Set, 제한된 효과·입자, 정적 예제 복제를 사용합니다. 실제 GPU에서 목표 프레임률 달성을 주장하지 않습니다.

## 28. 확인·수정한 결함

초기 인구 미배정으로 생기던 무인 발전, 부양 중심 편향, 도로 밖 방어시설, 재건 자재 과소 청구, 자유 건설 재난 해제 시 대피 인구 누락, 대피 경로 표시의 잘못된 연결, 보고 누적 20회 이후 집계, 생존 일반 공급 정지와 자유 건설의 강풍 반복을 수정했습니다.

## 29. 제한

풍하중·가림·국소 중력은 게임용 근사입니다. 중력은 구조 하중에 적용하며 전역 표시 질량과 부양 여유는 실제 질량을 유지합니다. 비상 배터리의 용량은 기존 배터리와 같은 180입니다. 수리 드론은 작업 표시이며 개별 이동 경로·충돌을 시뮬레이션하지 않습니다. 전력·절약 정책의 산업 감축률은 같습니다. 실시간 관측의 정확도 차이는 정보 표시이며 예보 자체가 오차를 만드는 확률 모델은 아닙니다. 10웨이브 장기 플레이·모든 난이도·모든 랜덤 시드와 실제 GPU 성능은 추가 검증 대상입니다.

## 30. Phase 7 준비

독립된 재난 상태·저장·순수 계산 모듈을 추가했습니다. 다음 작업은 사용자 지시대로 Phase 7 원문을 읽고 세계 지도·공중섬·비행선·교역·연구·Chapter 6을 기존 게임 위에 연결하는 것입니다. 7단계 기능을 6단계 완료 기능으로 표시하지 않습니다.
