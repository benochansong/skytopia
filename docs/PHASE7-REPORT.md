## 1. Phase 1–6 실제 구현 상태

기존 낙하 블록·보관·회전·구조 손상·부양·다층 건설·도시 경제·캠페인·재난 기능을 유지합니다. Phase 6의 PR #5는 단위 검사, 빌드, Chrome 브라우저 CI를 통과했습니다. 이전 25개 미션은 새 월드를 강제로 생성하지 않습니다.

## 2. 수정한 기존 핵심 기능

게임 규칙은 순수 TypeScript에 유지했습니다. 월드 문맥을 구조·부양·생산·전력 수요·공급 가중치·캐시에 연결했습니다. 월드에서 수동 선택한 설계도는 유료 배치 경로를 사용합니다. 단일 수도의 손실이 남은 도시의 시뮬레이션을 중지하지 않습니다.

## 3. 다중 도시 아키텍처

`Game.world`는 버전 1의 월드 상태를 보유하며, 도시 레코드는 재귀 월드와 전역 캠페인을 제외한 로컬 Game을 가집니다. 화면의 Game은 활성 도시를 나타냅니다. 전환·행동·저장 전 활성 상태를 도시 레코드에 동기화하고, 월드 액션 후 활성 도시를 다시 연결합니다. 최대 6도시·24선박·24항로·12교량입니다.

## 4. 저장 데이터 마이그레이션

기존 도시 v1–v5의 검증·마이그레이션 경로와 원본 키를 유지합니다. 기존 도시를 수도로 가져올 때 건물, 인구, 큐, 보관 블록과 피해 상태를 보존하며 경제 이전의 주민은 실제 주거에 배정합니다. 문명은 `skytopia.world.v1`, WORLD LAB은 `skytopia.worldlab.v1`에 저장합니다. 캠페인은 v4이며 v3/v2/v1을 읽고 원본을 덮어쓰지 않습니다.

## 5. 세계 지도

SVG 지도에서 이동·확대·축소, 미발견 섬, 발견한 자원, 도시와 실제 비행 진행률, 교역로와 교량을 표시합니다. 지도에서는 Three.js Canvas를 마운트하지 않습니다. 미발견 섬의 세부 자원은 탐사 전 공개하지 않습니다.

## 6. 공중섬 생성

시드 기반 난수로 12–20개 섬을 생성합니다. 첫 하늘·에메랄드·철·빙결·에테르·잃어버린 천상 6지역에 위치, 바위 질량, 코어 부양 특성, 생산 계수, 기온, 바람, 위험과 유적을 배정합니다. 같은 시드는 같은 결과를 만듭니다. 섬 윤곽은 지도에 표현하며, 신규 정착지의 기초 배치는 공통 설계입니다.

## 7. 탐험

실제 정찰·탐사·연구선을 건조하고 왕복 연료를 확보해 출항합니다. 도착해야 발견과 유적 기록이 반영됩니다. 유물은 선박 화물로 귀환해야 도시에서 사용할 수 있습니다. 발견한 자원의 열람과 개척 후보 선택을 따로 저장합니다.

## 8. 새로운 도시 개척

개척선은 섬별 자재 60–90, 식량 30, 에테르 10, 주민 20과 운영비 크레딧 150을 실제 출발 도시에서 가져갑니다. 자재는 정착 패키지에 소비하고, 식량·에테르·운영비는 새 도시로 이전합니다. 취소한 개척 예치금은 실제 귀항 후 환급됩니다. 동시 개척을 포함해 최대 도시 수를 검사합니다.

## 9. 도시별 독립 운영

시설·주민·물리 창고·전력·경제·재난·구조·건설 큐·보관·배치 시한·층·카메라가 도시마다 분리됩니다. 희귀 자원은 도시 코어의 제한된 별도 재고이며 국제 창고가 용량을 늘립니다. 공통 무한 창고를 사용하지 않습니다.

## 10. 비활성 도시 시뮬레이션

활성 3D 도시는 0.25초 고정 단계, 비활성 도시와 지도상의 도시는 누적 1초 단계를 사용합니다. 경제·이주·피해·수리·날씨는 계속 진행하며 블록 시한은 활성 도시에서만 감소합니다. 이동 전 누적 시간이 보존됩니다. 오프라인 시간을 소급하지 않고 숨긴 탭은 기존 일시정지 정책을 따릅니다. 구조 손상은 1초 적분 근사이므로 활성 도시와 매 프레임 수치가 완전히 같지는 않습니다.

## 11. 도시 전문화

균형, 농업, 산업, 에너지, 연구, 주거, 무역을 지원합니다. 농업·산업·에너지는 실제 생산, 연구는 RP, 주거는 행복도, 무역은 적재·하역 속도 25% 증가에 영향을 주고 공급 블록 가중치도 바뀝니다. 특화 변경에는 도시별 자재 10과 크레딧 50이 필요합니다. 지역의 비옥도·광물·에테르·추위·풍하중도 계산에 반영합니다.

## 12. 공중항구

소형·일반·대형·탐사 항구는 실제 기반, 도로, 노동력, 전력과 전면 접근 공간을 요구합니다. 항구 크기별 처리 슬롯을 사용하며 적재와 하역에 시간이 걸립니다. 항구가 정지하거나 창고가 가득 차면 물자는 선박에서 대기합니다.

## 13. 비행선 종류

정찰 10/1.8, 탐사 30/1.3, 소형 화물 80/1.2, 대형 화물 250/0.8, 개척 150/0.9, 구호 100/1.5, 연구 50/1.0의 적재량/속도 계수를 사용합니다. 비용·건조시간·항속·내후성·항구 등급이 다릅니다. 대형 화물선과 연구선에는 금속도 필요합니다. 7종을 구분하는 절차적 3D 모델을 표시합니다.

## 14. 비행선 운항

건조·정박·적재·출발·항해·회피 대기·접근·하역·수리·귀항 상태를 보존합니다. 거리·적재량·HP·날씨·연구가 속도와 연료에 영향을 줍니다. 위험을 허용한 선박은 피해를 받을 수 있으며 임의로 삭제하지 않습니다. 가동 중인 세계 관측소는 예보 단계부터 경로 위험을 감지합니다. 위험 회피는 대기 방식이며 다중 경유지 우회 경로 탐색은 구현하지 않았습니다.

## 15. 실제 화물 운송

기본 자원·희귀 자원·승객을 적재할 수 있습니다. 출발 도시에서 차감한 물자는 선박에만 존재하고 도착 시 실제 수용량만큼 이전합니다. 승객은 연결된 주거에서 출발해 도착지의 연결·전력·주거·식량 조건 안에서만 하선합니다. 운송 중인 사람은 도시 인구에 중복 포함하지 않습니다.

## 16. 자동 교역로

출발지·도착지·선박·자원·최대 적재·출발지 최소 비축·목적지 목표량·간격·우선순위·위험 허용을 사용합니다. 이미 출발한 화물을 목적지 예약량에 포함합니다. 자동 운송 후 빈 배는 귀항하며 중지한 항로의 운송 중 화물은 그대로 보존됩니다.

## 17. 자원 보존

화물 변경은 공통 재고 함수로 처리합니다. 부분 하역, 창고 포화, 왕복 연료 선지급과 잔여 연료 반환, 취소 귀항, 승객 이동, 개척 예치금을 검증합니다. 거래 ID는 단조 증가하며 최근 영수증 128개를 보관합니다. 저장은 월드 전체 상태를 한 번에 직렬화하므로 이미 도착한 거래를 재실행하지 않습니다.

## 18. 고대 유적

3개 이상의 유적 지역이 생성됩니다. 기록 후 나중에 돌아오거나 회수를 선택합니다. 한 유적의 유물은 한 번만 회수하며 연구 데이터 10과 고대 합금 8이 실제 귀환 화물이 됩니다. 유물 분석소는 데이터를 RP로 변환합니다.

## 19. 연구 시스템

구조·에테르·도시·산업·운송·회복력 6분야에 각 3개, 총 18개 기술을 제공합니다. 실제 가동 연구소, 선행 기술, RP, 자재·에테르·크레딧·데이터와 연구 시간이 필요합니다. 연구소 정지 시 진도가 멈추며 완료 보너스는 파생 계산으로 한 번만 적용됩니다. 기존 캠페인 시설은 다시 잠그지 않습니다.

## 20. 고급 에테르 기술

연료 절감, 부양 12% 증가, 실제 무게와 전력을 갖는 분산 부양 코어, 고순도 정제, 경량화 등을 구현했습니다. 분산 코어는 기존 전력·구조·관성·재난 계산에 참여합니다. 넥서스도 파괴와 전력 부족으로부터 면역이 아닙니다.

## 21. 도시 간 재난 대응

구호선은 실제 식량·자재를 운송하며 부두 처리에서 우선됩니다. 지역·개별 도시의 재난은 항로 위험에 반영되고 손상된 항구는 정비·회복 전 사용할 수 없습니다. 수송 물자는 도시의 기존 식량·수리 경제에 들어갑니다. 자동으로 모든 재난을 해결하는 지원 버튼은 없습니다.

## 22. 문명 전체 관리

도시별 인구·안정도·전력·생산·재고·회복력, 최근 배송 기록과 우선순위 경고를 표시합니다. 안전·교역·특화·인구·기술·넥서스의 조합으로 6문명 단계를 판정합니다. 전역 회복력은 구조 50%, 기존 방재 평가 15%, 전력 15, 식량 비축 15, 작동 교역 5의 도시 평균입니다. 수도 이전에는 실제 중앙 관제소와 안정도 80이 필요합니다.

## 23. Chapter 6 미션

26은 항구 건설·3섬 탐사·자원 열람·개척 후보·귀환, 27은 유물 귀환과 고급 부양 연구, 28은 두 개척 도시·농업/산업·실물 자동 교역, 29는 단절 항로 복원·실제 구호 수송·세 도시 안정 운영, 30은 네 도시·총인구 1000·세 특화·5배송 항로·세계 생산·전력·안정도·회복력·넥서스를 요구합니다. 후반 미션은 이미 성장한 도시를 시작 조건으로 제공하며 결과 플래그를 미리 설정하지 않습니다.

## 24. SKYTOPIA NEXUS

## 25. 최종 엔딩

## 26. 자유 문명 모드

## 27. WORLD LAB

## 31. 자동 테스트

월드 검사 24개(26–30 실제 승리 경로 포함)를 통과했습니다. 최종 전체 회귀는 21파일 230개 모두 통과했으며 처리되지 않은 오류는 없었습니다. 타입·빌드·형식·프로덕션 테스트 연결 제거도 확인했습니다. 테스트를 위해 승리 상태를 직접 설정하지 않습니다.

## 32. 브라우저 검사

새 문명 시작 → 탐사 → 두 도시 개척 → 실제 자재 배송 → 월드 저장/복원 → 한·영 전환 → 단일 Canvas 전환을 검사합니다. 최종 미션의 유료 넥서스 건설과 엔딩·계속하기도 별도로 검증합니다. Chrome 21개 고유 플레이 흐름, Edge 캠페인·월드 6개 흐름을 통과했습니다. 마지막 캐시·화면 수정 후 Chrome 월드 2개와 수동 렌더링 검사도 다시 통과했습니다. 실행 상세는 검증 기록에 기재합니다.

## 33. 성능 측정

최대 도시 수를 제한하고 활성 도시만 3D로 렌더링합니다. 비활성 도시를 1초 단계로 처리합니다. 3/6도시 CPU·저장 크기·복원 및 SwiftShader 실측을 검증 기록과 원시 JSON에 기록합니다. 6도시용으로 계산 캐시를 제한적으로 늘렸습니다. 실제 GPU의 목표 FPS는 미검증입니다.

## 34. 발견한 버그와 제한

승객 하역에서 비주거 시설의 0명 주민 키가 만들어지는 문제, 재난 빈도 0에서 강제 예보 복구 시간이 저장 한도를 넘는 문제, 엔딩 도시 전환 시 전역 승리 상태가 로컬 상태로 바뀌는 문제를 수정했습니다. 추가로 지도 CSS 충돌, 월드 블록 시한 저장 한도, 비활성 시간의 블록 시한 차감, 선택기 접근성 이름을 수정했습니다. 자세한 결과는 최종 검증 기록에 남깁니다.

## 35. 미구현·근사 기능

경유지 기반 최적 우회 경로, 개별 시민의 탑승 보행 AI, 절차적 3D 섬 지형 재생성, 실물 탄성 케이블 교량, 전용 녹음 음악·음성, 과거 도시 스냅샷 영상은 없습니다. 교량은 실제 앵커 추가 하중과 안정도 기반 손상, 제한된 화물 이동을 사용하는 게임 근사입니다. 원격 서버·멀티플레이·온라인 거래·계정은 추가하지 않았습니다.

## 36. Phase 8 준비

시드, 고정 시간, 독립 도시, 명시적 화물과 거래 상태, 경계 검증을 재사용할 수 있습니다. 온라인 권위 서버, 동기화·결과 검증·매치메이킹·부정행위 방지는 별도 설계와 구현이 필요합니다. 이번 변경에서 온라인 기능이 준비 완료되었다고 주장하지 않습니다.
