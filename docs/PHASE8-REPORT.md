# Phase 8 — SKY RIVALS 개발 보고

2026-11-27 · v0.8.0. 원본 요구사항의 우선순위 0–4를 중심으로 실제 2인 온라인 기반을 구현했다. 아래의 미구현 범위를 포함하므로 Phase 8의 모든 확장 기능이나 정식 출시 완료를 뜻하지 않는다. 실제 테스트 수치와 화면은 `VERIFICATION.md`에 기록한다.

## 1. Phase 1–7 실제 상태

기존 순수 TypeScript 도시/구조 규칙, 한국어·영어, 30미션 캠페인, 수직 건설, 재난, 생존, 세계 탐사·개척·운송·연구가 유지된다. 시작 지점은 Phase 7 커밋 `993a7b2`이며 기존 검증 기록을 `VERIFICATION-PHASE7.md`로 보존했다.

## 2. 기존 기능 수정

온라인 포트가 활성화되면 로컬 규칙 적용·자동 저장·개인 일시정지를 차단한다. 커서·회전·카메라 미리보기는 유지한다. 종료 시 온라인 진입 전 게임 상태를 복원한다. 메뉴를 Phase 8 버전으로 갱신했다. 다른 프로젝트와 포트가 충돌한 테스트 환경을 5188 전용 포트와 기존 서버 재사용 금지로 수정했다.

## 3. 서버 아키텍처

Node 24 상주 HTTP/WebSocket 프로세스, SQLite 영구 저장, 방별 권위 시뮬레이션이다. `server/service.ts`는 인증·방·진행·동기화를 담당하고 `src/game/online`에서 기존 순수 도시 규칙을 호출한다. 브라우저와 서버가 같은 배치·구조·경제 규칙을 사용한다.

## 4. 네트워크 방식

브라우저 기본 WebSocket과 서버 `ws`. 서버 4Hz, 정기 전송 2Hz, 중요한 행동과 로비 변경은 즉시 전송한다. TLS는 운영 역방향 프록시에서 처리한다. 짧게 실행되는 HTTP 함수는 사용하지 않는다.

## 5. 플레이어 세션

서버가 256비트 불투명 토큰과 UUID를 발급한다. DB에는 해시만 저장하며 30일 유효하다. 같은 이름도 다른 세션이다. 같은 토큰의 새 연결은 이전 연결을 대체한다. 이름으로 권한을 판정하지 않는다.

## 6. 방 생성·참가

방 이름, 대전/협동, 공개 여부, 10/15분, 바람 재난, 관전자 허용을 선택한다. 최대 2명의 플레이어, 4명의 관전자다. 진행 중인 방에 플레이어가 새로 들어갈 수 없다.

## 7. 초대 코드

서버 암호학적 난수의 8자리 코드다. 공개 목록은 공개 방만 보여주며 비공개 코드는 초대 권한으로 취급한다. 요청 속도와 접속 수를 제한한다. 코드를 가진 사람이 참가할 수 있으므로 비밀번호 기반 접근 정책은 아니다.

## 8. 로비

게스트 접속·방 생성·코드 참가·관전·목록 새로고침·준비 표시·방장 시작·연결 상태를 제공한다. 두 명이 연결되고 준비해야 시작되며 3초 카운트다운 후 같은 조건으로 진행된다.

## 9. 실제 매치메이킹

서버 대기열의 서로 다른 두 실제 세션을 공개 SKY DUEL 방으로 묶는다. 취소 가능하며 봇이나 가짜 상대를 넣지 않는다. MMR·지역·핑 기반 매칭은 없다. 준비/시작 절차는 유지한다.

## 10. SKY DUEL

동일 도시와 자원으로 독립된 도시 두 개를 운영한다. 서버 시간 10/15분 종료, 붕괴, 포기, 접속 유예 만료로 결과가 확정된다. 상대 도시를 읽기 전용으로 관찰할 수 있다. 비랭크 게스트 경기다.

## 11. 동일 블록 공급

같은 시드와 고정 공급 문맥을 사용하며 도시 상태에 따른 적응형 가중치를 넣지 않는다. 첫 여섯 블록은 공통 입문 순서, 이후 동일한 시드 기반 bag다. 각자의 소비 순서에 따라 진행하며 보관은 남은 시간을 재설정하지 않는다. 현재·다음 세 개·보관만 자신에게 보인다. 20초 만료 시 블록은 재활용되며 온라인 재활용으로 자재를 생성하지 않는다.

## 12. 서버 건축 검증

서버가 발급한 hand token, 명령 순서, 경기 상태, 소유 도시, 좌표·회전, 점유·코어·지지, 비용, 건설 상한을 검증한다. 클라이언트는 도시나 점수를 제출할 수 없다. 건설·보관·재활용·수리·보강·철거·업그레이드·긴급 지원은 서버 승인 후 반영한다.

## 13. 점수·승리

인구 25%, 구조 25%, 경제 20%, 연결 15%, 행복 10%, 공간 효율 5%의 최대 10,000점이며 세부 점수를 결과에 표시한다. 목표 충족 수 → 점수 → 안정 → 공간 효율 순으로 비교하고 같으면 무승부다. 붕괴·포기·유예 만료는 별도 종료 사유다. 계산 입력은 서버 도시 상태뿐이다.

## 14. 구조 공학 경쟁

독립 경기 모드는 미구현이다. 대전·협동의 구조 계산, 붕괴, 수리·보강은 실제 기존 규칙을 사용한다.

## 15. 제한 블록 퍼즐 경쟁

미구현이다. 싱글플레이의 기존 제한 블록 도전은 유지된다.

## 16. 재난 생존 경쟁

독립 생존 대회는 미구현이다. 현재 방 재난 옵션은 같은 바람 재난 일정과 기존 재난 엔진을 적용한다. 구조 설계와 방어 상태에 따른 결과는 각 도시에서 계산한다. 자유롭게 전 재난 종류를 고르는 경쟁 설정은 제공하지 않는다.

## 17. 문명 발전 경쟁

Phase 7 다도시 문명 레이스는 미구현이다. 이를 완료된 메뉴로 표시하지 않는다.

## 18. 협동 도시

하나의 실제 도시·창고·재정을 공유하고 블록·대기열·보관·타이머는 플레이어별이다. 서버가 순서대로 요청을 처리하여 충돌 시 한 건만 승인한다. 거절된 사람의 블록·자원은 유지된다. 건설/경제와 구조/방재 역할을 나누도록 안내하되 강제하지 않는다. 핑과 위치 이동, 수리·보강, 방장 철거 권한, 공동 승패를 제공한다. 새 시설 4개·인구 30·안정 75%·식량 자급·전력 충족을 10초 유지하면 승리한다.

## 19. 협동 문명

영구 협동 월드, 다도시 역할 분담, 도시 소유권은 미구현이다. 두 사람이 같은 단일 도시를 운영하는 범위다.

## 20. 플레이어 교역

온라인 거래소·개인 자원 교환은 미구현이다. Phase 7 싱글플레이 도시 간 운송은 유지된다.

## 21. 동기화

전체 초기 상태, 최상위 필드 변경분, revision/base, 주기적 전체 스냅샷을 사용한다. 순번 차이를 발견하면 재동기화한다. 상대의 공급 RNG와 숨겨진 queue는 전송하지 않는다. 카메라·미리보기는 로컬이며 최종 도시를 낙관적으로 변경하지 않는다. 느린 소켓의 전송 큐를 제한한다.

## 22. 재접속

같은 브라우저 토큰으로 재인증하면 도시·시간·hand·명령 순서를 복원한다. 살아 있는 탭의 미승인 명령은 같은 UUID로 재전송한다. 대전 시간은 한 명이 끊겨도 진행한다. 협동에서 모두 끊기면 일시 정지하며 60초 후 무효 종료한다. 서버 프로세스 자체 재시작은 경기 복원이 아닌 명시적 무효 처리다.

## 23. 온라인 계정

인증된 임시 게스트 세션만 구현했다. 이메일/OAuth, 비밀번호, 계정 복구·기기 간 로그인은 없다. 브라우저 데이터가 삭제되면 게스트 기록 접근권을 잃는다. 공식 랭킹 계정처럼 표시하지 않는다.

## 24. 전적

게스트별 최근 20개 확정 결과를 DB에서 조회한다. 게임 ID, 시간, 참여자, 종료 사유, 승자, 세부 점수를 저장한다. 같은 경기 결과는 한 번만 확정되며 클라이언트가 바꿀 수 없다.

## 25. 랭킹

글로벌 랭킹과 MMR은 미구현이다. 로컬 점수를 글로벌 순위처럼 표시하지 않는다.

## 26. 시즌

시즌 일정·보상·리셋은 미구현이다.

## 27. 관전

방장이 허용한 코드로 최대 4명이 관전할 수 있다. 서버는 hand를 보내지 않고 모든 변경 명령을 거절한다. 경기 도중 관전자가 들어올 수 있다. 개인 토큰이나 상대의 전체 공급 시드는 노출하지 않는다.

## 28. 리플레이

타임라인 재생·되감기·결정적 재시뮬레이션은 미구현이다. 전적의 최종 점수를 리플레이라고 부르지 않는다.

## 29. 부정행위 방지

Origin 허용목록, 최초 인증, 서버 권한, 엄격한 메시지 스키마와 16KiB 상한, 요청 속도 제한, UUID/sequence 중복 방지, hand token, 최종 점수 서버 계산을 적용했다. 전적에 랭킹 점수를 부여하지 않으므로 임시 계정으로 공식 랭킹을 조작하는 기능은 없다. 상용 부정행위 탐지·대규모 DDoS 방어는 아니다.

## 30. 데이터베이스

Node 내장 SQLite, WAL, 스키마 v1, 준비된 쿼리다. 미지원 버전은 시작을 거절한다. 세션 해시와 경기 시작/확정 결과를 영구 저장한다. 실행 중 서버가 사라진 경기는 다음 실행에서 무효로 정리한다. DB 백업·보존 절차는 운영 문서에 설명했다.

## 31. 싱글플레이 유지

온라인 세션 저장 키와 서버 DB가 기존 모든 저장 슬롯과 분리된다. 온라인 게임을 로컬 캠페인·생존·세계 저장에 쓰지 않는다. 온라인 연결 없이 메뉴와 기존 게임을 실행할 수 있다. 회귀 검증 상세는 검증 문서에 기록한다.

## 32. 변경 파일

핵심 신규 경로: `src/game/online/{protocol,match}.ts`, `src/multiplayer/{port,client,OnlineUI,online.css}`, `server/{config,database,service,index}.ts`, `server/tests/online.test.ts`, `e2e/online.spec.ts`, `scripts/online-load.ts`, `tsconfig.server.json`. 기존 변경은 게임 스토어·App·메뉴·중앙 rules·Vite/Playwright·CI·패키지·환경 예시·문서다. 원본 Phase 8 요구사항을 보존했다.

## 33. 클라이언트 실행

`npm ci` 후 `npm run dev -- --port 5188 --strictPort`. 배포 빌드는 `npm run build`, 출력은 `dist/`. 별도 WSS 서버는 빌드 시 `VITE_MULTIPLAYER_URL`을 설정한다.

## 34. 서버 실행

Node 24에서 개발 `npm run server:dev`, 배포 `npm run server:build` 후 `npm run server:start`. 기본 데이터 경로는 `server-data/skytopia.sqlite`, 포트 8787. 환경 변수와 HTTPS origin 검증은 중앙 설정 모듈에서 처리한다.

## 35. 두 브라우저 테스트

서로 다른 브라우저 프로필에서 각자 연결하고 초대 코드로 같은 방에 들어가 준비/시작한다. 새로고침·관전·공동 위치 배치·결과 조회를 검증한다. 자동화는 `npx playwright test e2e/online.spec.ts --project=chrome`이다.

## 36. 실제 온라인 테스트

실제 로컬 WebSocket 서버와 독립 세션으로 검사했다. 서버 테스트는 동일 공급, 스키마, 환경 설정, 재난 일정, 정상 건설의 협동 승리, 빠른 매칭, Origin/큰 프레임 거절, 중복 요청, 충돌, 재접속, 관전, 유예 만료, DB 재시작을 포함한다. 브라우저 최종 결과 및 회귀 수치는 `VERIFICATION.md`에서 확인한다. 공개 인터넷 서버는 배포하지 않았다.

## 37. 성능·부하

재현 스크립트 `npx tsx scripts/online-load.ts`는 실제 소켓으로 2/4/8개 대전을 만들고 시뮬레이션·동기화 비용을 측정한다. 원시 JSON은 `docs/verification/phase8-load.json`에 기록한다. 초기 도시·loopback 부하이며 최대 건설·TLS·WAN·장시간 누수·상용 동접 규모를 증명하지 않는다.

## 38. 배포 환경

정적 클라이언트와 영구 디스크를 가진 상주 Node 24 서버, HTTPS/WSS 프록시가 필요하다. `APP_ORIGIN` 또는 `APP_DOMAIN`을 운영에서 필수로 요구한다. 도메인 리터럴을 코드에 넣지 않는다. DNS·인증서·Gabia·Cloudflare 라우팅 변경은 수행하지 않았다.

## 39. 비용·외부 서비스

로컬 실행에 결제·외부 API·클라우드 계정이 필요하지 않다. 실제 공개 운영은 VM/컨테이너·영구 디스크·트래픽·백업·관측 비용이 발생할 수 있으며 특정 요금이나 무료 운영을 보장하지 않는다. 유료 서비스를 생성하지 않았다.

## 40. 미구현 기능

독립 구조/퍼즐/생존 경쟁, 다도시 문명 경쟁, 영구 협동 월드, 온라인 교역, 정식 계정, MMR/글로벌 순위, 시즌, 리플레이, 자유 채팅/신고/차단/관리 UI, 다중 서버 확장이다. 메뉴와 설명에서 구현 상태를 명확히 구분한다.

## 41. 제한·위험

단일 프로세스·임시 게스트 기반이다. 서버 재시작 시 진행 도시가 복원되지 않는다. 높은 부하에서는 bounded catch-up으로 서버 시뮬레이션 시간이 실제 시간보다 느려질 수 있다. 서버는 최대 12개 방을 허용하지만 측정 결과에 따라 운영 한도를 낮춰야 한다. Node 24 SQLite의 실험적 API 경고, 소프트웨어 GPU 성능, 기존 Three 청크 크기 경고가 있다. `npm audit`의 기존 Zod/테스트 도구 항목은 검증 문서에 별도로 기록한다.

## 42. 출시 전 추가 작업

실제 두 인터넷 회선의 WSS·지연·패킷 손실 검증, 장시간 최대 도시 부하, 서버 복원/백업 훈련, 정식 인증과 복구, 운영 도구, 모더레이션, 접근성·키보드 포커스 정밀 점검, 사람의 게임 밸런스 테스트와 보안 의존성 업데이트가 필요하다. 본 결과를 정식 출시 완료로 취급하지 않는다.
