# Phase 9 — GAMEPLAY POLISH 개발 보고

## 1. Phase 1–8 실제 상태

30개 캠페인, 건축 훈련, 구조·도시·수직·재난 실험실, 생존, 자유 건설, 최대 6개 도시의 세계와 실제 2인 대전·협동이 존재한다. 랭킹·시즌·정식 계정·리플레이는 구현되어 있지 않다. Phase 8 PR #7과 GitHub CI는 통과했다.

## 2. 발견한 문제

운영체제별 키 반복, 회전 후 인접 위치 복구 부재, 무제한 재활용, 위험한 시간 만료 자동 배치, 결과 뒤 남는 온라인 오류, 사진 모드 부재를 확인했다. 자세한 근거는 PHASE9-AUDIT.md에 있다.

## 3. 심각도

자원·공급 악용과 입력 격리는 High, 배치 보정·사진·온라인 결과 안내는 Medium, 기존 도시 조언 순서는 Low로 분류했다.

## 4. 수정한 버그

3초 재활용 제한을 저장 및 서버 손패에 유지한다. 시간 만료는 실제 위험 단계 2 이상 후보를 재활용한다. 상대 도시·관전자에게 가짜 건축 고스트를 보이지 않는다. 경기 종료 시 임시 오류를 제거한다. 카메라 초점 범위를 실제 건축 경계까지 확장했다.

## 5. 건축 입력

키를 누르면 즉시 한 칸 이동한다. 자체 반복 타이머가 이후 입력을 처리하고 긴 지연 뒤 입력을 몰아서 실행하지 않는다. 모달·포커스 변경·숨김·키 해제 시 반복을 중단한다. 마우스의 기존 정지 포인터 및 드래그 보호를 유지했다.

## 6. 이동·회전

반복 대기 120–600ms, 간격 50–250ms를 설정한다. 회전이 불가능한 위치에서는 선택적으로 같은 층 한 칸 안의 안전한 위치만 탐색한다. 보정은 실제 validatePlacement를 통과해야 한다.

## 7. 카메라

회전·확대 감도 0.3–2배, 최근 건축·위험 구역 초점, 사진 모드 자유 카메라를 제공한다. 기존 360도 회전과 층별 시점을 보존했다.

## 8. 다층 건축

스냅은 층을 변경하지 않는다. 기존 수직 점유·지지·교통·전력 모듈이 최종 판정을 유지한다. 보정 때문에 위층으로 순간 이동하거나 충돌을 무시하지 않는다.

## 9. 배치 미리보기

기존 네 단계 위험 색상과 이유·아이콘을 보존했다. 칸 수·질량·실제 비용을 표시하고 펼치기 또는 안내형 설정에서 실제 배치 투영의 안정도·전력·수용량을 보여준다. 주민 정착 이후의 확정 생산량으로 오인하지 않도록 설명한다.

## 10. 스마트 스냅

옵트인 한 칸 스냅이다. 유효한 사용자의 원래 좌표를 먼저 보존하고, 이동 방향 다음 고정 순서로 검사한다. 전문가형은 스냅·회전 보정을 끈다. 시설 추천이나 최적 도시 자동 건설은 하지 않는다.

## 11. 공급과 대기

배치 함수가 같은 입력 처리 중 다음 블록을 준비한다. 애니메이션 대기를 추가하지 않았다. 자유 건설의 일반·구조 도전은 기존 동일 블록 고정 공급 대신 실제 시드 공급을 진행한다. 기존 캠페인 낙하 시간·난이도 배율은 유지했다. V를 누르면 싱글플레이 낙하 타이머만 빠르게 진행하며 경제 시간을 가속하지 않는다.

## 12. 보관·재활용

보관은 기존 마감 시간을 유지한다. 자원이 제한된 무제한 공급 모드의 수동 재활용은 3초 간격이다. 온라인은 서버 시간과 개인 손패의 재활용 가능 시각을 사용한다. 무제한 자원 실험과 이미 블록 예산으로 제한된 퍼즐은 예외다. 기존 주문 제작·실제 비용·생산 대기를 유지했다.

## 13. 완료 피드백

즉시 건축, 연결 복구, 전력 균형 회복, 안정도 개선, 공간 확장을 실제 전후 분석으로 표시한다. 짧은 메시지는 자동으로 사라지고 다음 입력을 막지 않는다.

## 14. 콤보·시너지

실제 개선에 대한 피드백만 추가했으며 통화·자원을 증식시키는 보너스는 없다. 기존 도시 시설 및 세계 특화 시너지는 그대로 사용한다. 별도 연속 점수 콤보나 새 중첩 경제 보정은 추가하지 않았다.

## 15. 구조 위험

가장 위험한 구조물로 바로 초점을 이동한다. 위험 후보 자동 건설을 막고, 치명적 구조 경고는 숨김 중에도 표시한다. 실제 하중·기울기·붕괴 판정은 기존 순수 TypeScript 모듈을 사용한다.

## 16. 도시 운영

최대 세 개의 기존 조언을 유지하며 필수 전력을 식량보다 먼저 표시한다. 식량 생산·소비·비축, 전력 공급·수요의 실제 수치와 해결책을 연결한다. 긴급 기아 경고는 숨김 요청보다 우선한다. 기본 정보의 대규모 재배치는 하지 않았다.

## 17. 캠페인

기존 30개 단계의 목표·체크포인트·중간 목표·선택 목표·별 평가를 보존했다. 모든 미션을 새 목표로 교체하지 않았다. 안내형 배치 예측과 입력 보정은 캠페인에도 적용된다. 제한 블록 퍼즐의 소비 제한을 유지한다.

## 18. 생존과 자유 건설

기존 예보·복구 시간·선택 보상을 유지한다. 자유 건설 메뉴에 편안한 건설(무제한 자원), 일반(무작위 공급), 구조 도전(전문가 물리), 생존(기존 재난 웨이브) 프리셋을 연결했다. 별도 시뮬레이션 엔진을 만들지 않았다.

## 19. 세계 운영

도시 목록을 실제 붕괴·구조 위험·진행 중 재난·전력·식량 순으로 정렬한다. 식량 부족 도시에는 현재 순생산과 재고를 만족하는 다른 도시를 공급 후보로 표시한다. 항구·항로 유효성은 기존 운송 명령이 검증한다. 후보를 이미 운항 중인 항로로 표현하지 않는다.

## 20. 온라인

서버 권위, 동일 공급, 명령 ID 중복 방지, 충돌 시 한 번 소비, 재접속 유예를 유지한다. 결과의 목표 수와 실제 비교 순서를 보여준다. 공유 핑·진행률을 보존하고 확인 창을 기존 접근성 Dialog로 통일했다. 재활용 가능 시각을 버튼에 표시한다. 온라인 사진 모드도 서버 시간을 정지시키지 않는다. 상대의 실시간 고스트와 별도 공유 지출 장부는 아직 없다.

## 21. 승리·실패

기존 도시 평가·실패 원인·체크포인트·재도전을 보존한다. 대전 시간 종료는 목표 수 → 총점 → 안정도 → 공간 효율 순임을 결과에서 설명한다. 오프라인 연결 상태에서 방을 닫아도 서버가 즉시 포기로 확정되는 것처럼 설명하지 않는다.

## 22. 사진 모드

HUD·고스트·분석을 숨기고 싱글플레이 시간을 멈춘다. 실제 WebGL 프레임을 요청 시에만 PNG로 저장한다. 상시 preserveDrawingBuffer를 사용하지 않는다. Escape로 복귀한다. 온라인은 동일 기능에서도 경기 시간이 계속 흐른다. 시간대·날씨·고해상도 설정은 Phase 10 대상이다.

## 23. 저장 보호

도시 v5와 기존 슬롯을 유지한다. 선택적 polish.version=1 영역과 settings.controlsVersion=1에 명시적 경계를 두었다. 이전 저장은 신규 설정 기본값을 받고 기존 도시 데이터는 그대로 읽는다. 알 수 없는 polish 버전은 거부한다. 실행 취소·사진 상태·진단 로그는 저장하지 않는다.

## 24. 변경 파일

src/game/controls.ts, playFeedback.ts, src/stores/diagnostics.ts 및 기존 engine/storage/city/world/online 모듈; gameStore, Runtime, PlayTools, Interface, CityUI, WorldUI, CampaignControls, World 렌더러, 온라인 클라이언트·UI; polish 단위·브라우저 테스트와 문서. 상세 목록은 PR diff에 있다.

## 25. 실행·조작

`npm ci`, `npm run dev -- --port 5188 --strictPort`; 온라인은 별도 `npm run server:dev`가 필요하다. WASD/화살표 이동, Q/E 회전, Space 배치, C 보관, X 재활용, V 소프트 드롭, PgUp/PgDn 층, R/F 입체 회전. Ctrl+Z는 캠페인·세계·생존·온라인·전문가 제외, 다음 시뮬레이션 변경 전까지만 가능하다.

## 26. 단위 테스트

전체 251개 / 23파일이 527.27초에 통과했다. 이후 세계 자동 배치·정지 경계를 보완하고 세계 미션·운송·저장·엔진·새 규칙 87개를 121.95초에 추가 검증했다. 새 규칙 테스트는 총 9개이며, 전체 실행에는 실제 WebSocket 서버 13개가 포함된다.

## 27. 브라우저 테스트

변경 전 기본 흐름 5개가 통과했다. 변경 후 실제 대전·협동과 입력·사진·재활용 흐름이 통과했다. 설정 선택기의 접근성 이름 누락과 도구 위치 겹침을 실제 화면에서 발견해 수정했다. 최종 전체 결과는 VERIFICATION.md에 기록한다.

## 28. 개선 전후

이전에는 무제한 즉시 재활용이 가능했고 반복 속도는 OS에 의존했다. 이후 재활용 30회 연타는 한 번만 소비하고, 반복 지연·속도는 게임 설정을 따른다. 사진 PNG를 실제 다운로드했다. 단일 배치 처리 6.2ms를 측정했다. 변경 전 동일 지표가 없으므로 속도 향상률을 주장하지 않는다.

## 29. 성능

진단은 개발 모드의 메모리 내 최근 300건이며 사용자가 JSON을 내려받을 수 있다. 외부 전송·계정 식별·영구 텔레메트리는 없다. 위험 예측은 선택적으로 펼쳐 본다. 브라우저 측정은 SwiftShader이며 실제 GPU의 FPS나 사람의 만족도를 검증한 결과가 아니다.

## 30. 남은 개선

기존 낙하 시간의 전면 밸런싱, 장기 안전 실행 취소, 미션 전체 재설계, 순서에 따른 점수 콤보, 온라인 동료 실시간 고스트·지출 기록은 미구현이다. 현재의 제한을 UI와 문서에서 구분한다.

## 31. 미검증

사람 대상 첫 10분 재미 평가, 장시간 다양한 전략의 경제 균형, WAN 환경 공정성, 실제 GPU 60FPS, 모든 접근성 보조기기의 사용성은 확인하지 않았다.

## 32. Phase 10 준비

순수 게임 규칙·서버 판정과 표시를 분리했고 사진 캡처·카메라 설정을 마련했다. 최종 회귀 검증 후 Phase 10에서 실제 3D 에셋·환경·조명·사진 설정을 개선한다. Phase 11–13은 이번 작업에 포함하지 않는다.
