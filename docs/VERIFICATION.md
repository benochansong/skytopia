# Phase 1 검증 보고

검증일: 2026-11-26 (Asia/Seoul). 환경: Windows, Node.js 24.14.0, Chrome 158.0.8127.37, Edge 158.0.4370.33.

## 검증한 사용자 흐름

메인 메뉴 → 한국어/영어 전환 → 새 게임/훈련 시작 → 3D 섬 표시 → 카메라 회전·확대 → 이동·회전·배치 → 플랫폼 확장 → 도로·발전소 연결 → 인구 성장 → 미션 완료 → 자유 건설 → 저장 → 새로고침 → 이어하기.

서버/외부 API를 호출하는 기능은 없습니다. 확인 대상 경계는 **DOM 입력 → Zustand 상태 전이 → 순수 게임 규칙 → Three.js 장면/HUD → LocalStorage → 복구 검증**입니다.

## 직접 캡처 검토

- 메인 메뉴, 게임, 승리 화면, 1024×768 및 1440×900 화면을 캡처했습니다.
- 섬의 바위가 표면과 일부 시설을 가리던 렌더링 위치를 수정했습니다.
- 낮은 창 높이에서 훈련 패널이 건축 조작부와 겹치지 않게 측면 영역에 스크롤을 적용했습니다.
- 카메라 네 방향 회전 이후 마우스 배치 결과가 커서의 실제 격자 좌표와 일치함을 확인했습니다. 도시 기울기는 이때 활성화되어 있습니다.
- 카메라 회전 후 키보드 이동 방향, 상단 시점 전환, H 기본 시점 복귀를 확인했습니다.
- 주요 브라우저 흐름에서 페이지 예외와 콘솔 오류를 수집하여 없음을 확인했습니다.

## 구현 중 수정한 문제

- 초기 암석의 상단 면이 지면보다 높게 렌더링되는 문제.
- 훈련 단계 이전에 블록을 소모하면 안내 순서가 어긋나는 문제: 초기 단계 배치, 훈련 중 보관/재활용을 제어했습니다.
- 연결된 시설도 전력 부족일 때 비활성 표시가 필요했던 부분.
- Vite HMR 이후 테스트가 별도로 import한 상태 인스턴스를 읽던 테스트 기반 문제: 격리된 테스트 서버와 실제 앱 상태 연결로 수정했습니다.
- 낮은 해상도에서 훈련 카드와 하단 도크가 겹치는 문제.

- Linux CI에서 드러난 부동소수점 음의 0 좌표 차이: 입력 좌표를 정수/양의 0으로 정규화하고 회귀 테스트를 추가했습니다.
- 확대·화면 이동을 조합해도 카메라가 지형 내부로 들어가지 않도록 수직 각도와 지면 이동 범위를 제한했습니다.

## 남은 제한과 미검증 범위

- Firefox/Safari, 모바일 입력, 실제 저사양 GPU의 프레임률은 검증하지 않았습니다.
- 장시간 방치/최대 크기 도시의 메모리 프로파일링은 수행하지 않았습니다. 타이머·입력 리스너·AudioContext는 React effect 해제 시 정리합니다.
- Three.js 청크가 500kB를 초과합니다. 지연 로딩과 DPR 제한을 적용했지만 향후 로딩/렌더링 최적화 여지가 있습니다.
- 구조 파손·붕괴·수직 건축·정밀 하중 전달은 명세대로 후속 Phase로 남겼습니다.
- 공개 웹 호스팅, DNS, 인증서 설정은 수행하지 않았습니다. 결과물은 독립 실행 가능한 정적 웹 게임입니다.

## Phase 2 준비 상태

격자/공급/배치/연결/안정도/저장/렌더링 책임을 모듈별로 분리했습니다. `y` 및 `durability` 데이터 필드가 있으며 렌더링 기울기는 논리 좌표를 변경하지 않습니다. Rapier 같은 물리 엔진을 추가해도 기존 배치 판정과 저장 상태를 별도 유지할 수 있습니다. 다층·다중 부양장치는 저장 버전 업그레이드와 구조 그래프 구현이 추가로 필요합니다.
