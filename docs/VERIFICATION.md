# Phase 7 검증 기록

2026-11-27 · Windows · Node.js 24.14.0 · AMD Ryzen AI 9 365. [Phase 6 검증과 CI](VERIFICATION-PHASE6.md)를 보존했습니다. 이전 단계 완료 후 Phase 7을 개발했습니다.

브라우저 UI → Zustand → 순수 TypeScript 도시/월드/운송/연구/캠페인 → SVG 또는 단일 Three.js Canvas → 검증된 LocalStorage 복원을 확인합니다. 백엔드와 외부 서비스는 없습니다.

## 자동 검사

최종 전체 회귀는 npx vitest run --maxWorkers=1로 실행해 21파일 230개 모두 통과했습니다(502.69초, 처리되지 않은 오류 0). 초기 병렬 실행의 실행기 RPC 시간 초과가 재발하지 않았습니다. 월드 검사는 시드, 기존 도시 가져오기, 실제 탐사·개척·수송, 부분 하역, 귀항 취소, 저장 중복 방지, 승객 회계, 연구 비용, 교량 하중·화물, 재난 항로, 수도 손실 후 다른 도시 진행, 업적 중복 방지, 사용자 지정 블록 시한, 관측소 예보 감지를 다룹니다.

미션 26–30은 실제 유료 건설, 비행, 연구, 교역과 시간 진행으로 목표를 만족해 승리합니다. 승리 결과 플래그를 미리 설정하지 않습니다. 각 미션은 준비된 시작 도시와 예산을 사용하므로 26에서 30까지 하나의 월드를 계속 성장시키는 장기 캠페인 완주와 구분합니다.

타입 검사와 프로덕션 빌드는 통과했습니다. Three.js 청크 500kB 권고 경고는 남아 있습니다. 최종 빌드도 다시 통과했습니다(9.58초). 전체 Prettier 검사와 git diff --check도 통과했습니다. dist 검색에서 테스트 제어·성능 수집 전역 연결이 제거된 것을 확인했습니다.

## 브라우저

Chrome 전체 실행에서 20개 통과·1개 실패·수동 성능 6개 생략을 확인했습니다. 실패 원인은 실제 업적 목록 46개에 비해 프로필 총수를 34로 고정 표시한 것이었습니다. 총수를 목록 길이에서 계산하도록 수정한 후 해당 흐름이 통과해 21개 고유 흐름의 통과 근거를 확보했습니다. Edge에서는 기존 캠페인 4개와 신규 월드 2개, 총 6개 흐름이 통과했습니다. 캐시·도시 모드 표시 수정 후 Chrome 월드 2개 흐름과 3/6도시 렌더링 측정도 추가 실행해 3개 모두 통과했습니다.

1. 새 문명 → 탐사선/개척선 건조 → 미발견 섬 탐사 → 두 도시 개척 → 실제 자재 자동 배송 → 별도 월드 슬롯 저장·복원 → 한·영 UI → 지도 Canvas 0개/활성 도시 Canvas 1개.
2. 실제 미션 30 시작 상태 → 연합 연구 → 비용을 지불한 넥서스 배치 → 실제 목표 유지와 승리 → 엔딩 정지·다음·건너뛰기 → 자유 문명 계속 건설 → 보상 중복 없음.

시간이 필요한 구간은 test 모드 연결을 통해 실제 엔진을 고정 단계로 진행합니다. 넥서스는 실제 배치 검증과 비용 차감을 거치며 합법적 위치를 자동 탐색합니다. 모든 건물을 마우스로 일일이 배치한 수동 완주 검증은 아닙니다.

## 수정한 결함

- 선택기의 접근성 이름이 옵션 텍스트와 섞이던 문제.
- 기존 캠페인 지도 CSS가 SVG 섬에 적용되어 위치를 이동시키던 문제. 전용 클래스와 브라우저 회귀 단언을 추가했습니다.
- 승객 하역에서 비주거 시설에 0명 주민 레코드가 생겨 저장 검증이 실패하던 문제.
- 재난 빈도 0에서 수동 예보의 복구 시간이 저장 상한을 넘던 문제.
- 엔딩 도시 전환 때 로컬 승리 상태가 전역 결과를 덮어쓰던 문제.
- 월드 블록 시한 20초 초과가 레거시 도시 스키마와 충돌하던 문제. 월드 경계에서 0–120초를 검증하고 레거시 검증은 유지합니다.
- 비활성 누적 시간이 활성 도시의 낙하 시한에서 차감되던 문제.

캐시 한도는 도시 보고·도로·운영·연결망에서 12개 상태, 구조 분석에서 16개 상태로 늘려 6도시가 매번 서로의 캐시를 밀어내지 않게 했습니다. 무한 캐시를 도입하지 않았습니다.

## 성능

CPU 측정은 다른 검사를 종료한 상태에서 수행했습니다. 도시당 84시설, 워밍업 3회·표본 20회이며 중앙값 / p95(ms)입니다. [원시 결과](performance-world.json), 재현 스크립트: scripts/measure-world.ts.

Chrome 158.0.8127.37의 SwiftShader 측정도 통과했습니다. [원시 결과](performance-world-browser.json). 두 경우 모두 활성 도시의 draw call 397, triangle 31,460, geometry 409, texture 2로, 배경 도시 수만큼 3D 장면이 늘어나지 않습니다.

소프트웨어 렌더러에서는 낮은 프레임률이며 목표 FPS를 충족했다고 주장하지 않습니다. 실제 GPU와 장시간 플레이 검증이 남아 있습니다.

SKYTOPIA_WORLD_MEASURE=1로 e2e/world-performance.spec.ts를 실행하면 활성 3D 도시 하나와 나머지 배경 도시를 함께 진행하며 프레임 시간을 기록합니다. SwiftShader·개발 빌드·1440×900·DPR1 결과는 실제 GPU의 45–60FPS 보증이 아닙니다. 재난과 화물이 없는 준비된 수도 복제 부하이며 최대 시설 수·장시간 스트레스 측정과 구분합니다.

## 구현 경계

최대 6도시, 24선박, 24항로, 12교량, 최근 영수증 128개, 월드 저장 문자열 3백만 문자 제한이 있습니다. 비활성 도시는 1초 단위의 구조·경제·기상 근사를 사용하며 블록 시한은 활성 3D 도시에서만 감소합니다. 오프라인 진행은 없습니다.

경유지 최적 우회, 개별 시민 보행, 절차적 3D 지형, 탄성 케이블 교량, 과거 도시 영상, 녹음 음성, 온라인 기능은 구현 범위에 포함하지 않았습니다. 교량은 추가 앵커 하중과 안정도 기반 손상·유한 화물 이동의 게임 근사입니다. Firefox/Safari·모바일·장시간 메모리 안정성·모든 시드의 난이도 균형은 검증 완료로 주장하지 않습니다.
