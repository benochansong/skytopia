## 실제 입력과 사진 검증

- 키를 누른 채 유지하면 자체 반복 설정으로 여러 칸 이동하고 키 해제 후 더 움직이지 않는다.
- 회전·스냅은 한 칸 범위에서 실제 배치 판정을 통과하는 위치만 선택한다. 층을 바꾸지 않는다.
- 재활용 30회 연타에 공급 및 자원은 한 번만 바뀐다. 새 블록은 배치 함수가 반환하기 전에 준비된다.
- 개발 브라우저에서 동기 배치 처리 6.2ms를 측정했다. 실제 키보드 하드웨어 지연·네트워크 지연·사람의 만족도 측정은 아니다. 원자료: docs/verification/phase9-input.json.
- 사진 모드의 싱글플레이 시계는 정지하고 Space는 도시를 바꾸지 않는다. 요청 시 WebGL 프레임을 PNG로 다운로드한다. 실제 파일의 크기와 이미지를 확인했다.
- 위에서 보는 고정 카메라에서도 사진 모드 진입 시 자유 회전으로 전환한다. 복귀 후 HUD와 시간이 다시 작동한다.
- 설정을 저장하고 재실행해 스마트 스냅 선택이 유지되는지 확인한다. 자유 건설 프리셋은 기존 시뮬레이션을 사용한다.
- 온라인 사진 모드는 서버 시간을 멈추지 않는다. 온라인 저장 격리와 실제 협동 목표 달성을 검증한다.

## 발견 후 수정한 문제

설정 선택기의 접근성 이름에 옵션 텍스트가 섞여 브라우저가 정확한 이름을 찾지 못했다. 명시적인 aria-label로 수정했다. 처음 추가한 떠 있는 도구 막대가 자유 건설의 기상 설정 버튼을 가렸다. 해당 전체 실행을 중단하고 사진 버튼과 펼침 메뉴를 상단에 배치했으며 최종 전체 실행을 다시 진행했다.

프로덕션 빌드는 소프트 드롭의 stage import 누락과 브라우저 전용 진단 모듈이 서버 타입 검사에 포함되는 문제를 발견했다. import를 추가하고 진단을 src/stores로 분리한 뒤 클라이언트·서버 빌드를 모두 통과했다. 최종 경계 점검에서 도시 정지 중 소프트 드롭, 세계 모드의 위험 자동 배치, 온라인 로비의 불필요한 도구 표시도 보완했다.

## 저장 및 규칙 경계

도시 v5 슬롯, 캠페인 v4, 세계·생존 기록과 온라인 결과 DB를 유지한다. 선택적 polish.version=1과 controlsVersion=1의 기본값을 검증한다. 알 수 없는 polish 버전은 거부한다. 사진·진단·실행 취소 스냅샷은 영구 저장하지 않는다. 온라인 재활용은 서버 손패의 시각을 사용한다.

실행 취소는 다음 시뮬레이션 변화 전만 허용한다. 캠페인·세계·생존·온라인·전문가에서는 비활성화된다. 기존 미션 난이도와 낙하 시간 배율은 유지했다. 순서별 점수 콤보, 동료의 실시간 건축 고스트, 온라인 공유 지출 장부는 미구현이다.

## 한계

Chrome/Edge는 Playwright의 SwiftShader 설정이다. 실제 GPU 60FPS, WAN 환경, 최대 밀도 장시간 온라인, 사람 대상 첫 10분 플레이 재미, 다양한 전략의 경제 밸런스는 검증하지 않았다. 6개 성능 전용 브라우저 시나리오는 일반 회귀 실행에서 의도적으로 제외한다. Phase 8의 실제 서버 종료·재시작 및 부하 측정은 이전 기록을 참조하며 이번 단계에서 재측정한 것처럼 주장하지 않는다. 기존 의존성 audit 지적과 Node SQLite 실험 경고는 남아 있다. 공개 배포·병합·DNS 변경은 하지 않았다.
