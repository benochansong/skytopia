# Phase 2 검증 보고

검증일: 2026-11-26 (Asia/Seoul). Windows, Node.js 24.14.0, AMD Ryzen AI 9 365. Chrome 158.0.8127.37 / Edge 158.0.4370.33.

## 검증 경계

DOM 입력 → Zustand → 순수 게임 엔진/구조 해석 → Three.js 장면/HUD → LocalStorage → 스키마 검증/재구성의 전체 흐름을 확인합니다. 서버/API는 없습니다. 기존 [Phase 1 결과](VERIFICATION-PHASE1.md)는 별도로 보존했습니다.

## 자동 검증 결과

| ----------------- | --------- | -------------------------------------------------------- |

| Edge              | 8개 통과  | 동일한 플레이 흐름 8개                                   |

테스트 파일: `src/tests/{engine,storage,structure}.test.ts`, `e2e/{game,structure,performance}.spec.ts`. 성능 측정은 `SKYTOPIA_MEASURE=1`일 때만 실행하며 일반 CI에서는 그 1개만 생략합니다.

Edge의 최초 회전/배치 실행에서 동일 좌표 pointermove 재전송 문제가 발견되었습니다. 수정 후 해당 테스트를 Chrome과 Edge에서 각각 2회 연속 재실행해 4개 모두 통과했습니다. 표의 브라우저 결과는 전체 흐름 실행과 수정 항목 재검증을 합친 결과입니다. 프로덕션 번들에 테스트 상태 연결/성능 측정 전역이 남아 있지 않음도 확인했습니다.

## 필수 시나리오 A–J

| 명세            | 확인한 동작                                                             |
| --------------- | ----------------------------------------------------------------------- |
| A 대칭 질량     | 원점 대칭 공장 질량의 X/Z 중심과 모멘트가 0                             |
| B 편중 건설     | 같은 질량을 더 멀리 배치하면 모멘트 증가                                |
| C 부양 추가     | 무거운 구역 부양은 모멘트를 줄이고 반대편 부양은 악화                   |
| D 외곽 과부하   | 좁은 경로에서 연결부 과부하 및 시간 경과 피해                           |
| E 보강/경로     | 보강은 질량과 허용 하중을 함께 증가; 병렬 경로는 기존 경로 하중 감소    |
| F 부분 붕괴     | 지지 상실 구역만 제거, 다중 칸 시설 중복 제거 방지, 남은 도시 계속 실행 |
| G 연쇄 변화     | 외곽 발전소 제거 → 살아남은 회로 전력 0 → 8초 후 부양 감쇠 사건         |
| H 기울기/카메라 | 네 방향 회전 후 마우스 배치가 예상 격자와 일치, 카메라 상대 키보드 이동 |
| I 저장/복구     | 손상·수리 작업·보강·사건·붕괴 제거 상태·부양 타이머와 두 슬롯 복원      |
| J 회귀          | 메뉴·훈련·블록·보관·재활용·자동 낙하·확장·인구·미션·승리·저장 오류      |

추가로 프레임 분할과 무관한 고정 피해, 독립 부양 구역, 단계당 8칸 붕괴 상한, 위기 대응 유예와 패배, 비상 부양의 비용/수명/재사용, 비상 장치 지지점 상실, 긴급 설계도 사용 후 보관 잠금 보존, 사건 기록 상한 이후 최초 실패 원인 보존, v1 공급/회전/위치 보존, 미션 2–4의 완료 경로를 검증했습니다.

브라우저 테스트는 공급/커서/특정 손상 스냅샷을 지정하여 재현성을 확보합니다. 건축과 복구 UI는 실제 버튼/키/마우스로 조작합니다. 캠페인 승리와 치명적 실패는 엔진 시간을 가속하며, 실험실 수리와 자동 낙하/저장은 실제 시간을 기다립니다. 무작위 캠페인을 사람이 처음부터 끝까지 완주한 테스트는 아닙니다.

## 시각 확인

메뉴, 기존 훈련, 1440×900/1024×768 HUD, 미션 3 부양 분석, 실험실 연결부/수리/철거, 원인별 패배, 최대 도시를 캡처합니다. 문서 캡처는 `docs/images/`에 보존합니다. 기울기/카메라 보간 중 클릭이 표시된 예상 좌표와 달라지던 문제, HUD 내부 확인 창 잘림, 구조 사건 좌표의 불필요한 필드를 수정했습니다. 3D 경고 태그는 HUD 뒤에 배치합니다.

## CPU 실측

플랫폼 256개 + 건축물 255개, 직렬화 99,795바이트의 고정 합성 도시. 초기 워밍업 20회 뒤 측정했습니다. 렌더링과 분리된 Node/Vite-node 측정이며 벤치마크 결과는 환경·부하에 따라 달라집니다.

| 작업                          |   표본 |    중앙값 |       p95 |
| ----------------------------- | -----: | --------: | --------: |
| 전체 구조 평가                |    200 | 10.005 ms | 14.226 ms |
| 캐시 재사용                   | 10,000 | 0.0005 ms | 0.0010 ms |
| 손상 계산 포함 고정 구조 스텝 |    100 | 20.384 ms | 33.757 ms |
| 저장 검증 및 구조 재구성      |    100 | 12.195 ms | 16.525 ms |

[원본 JSON](performance-structure.json). 재현: `node node_modules/vite-node/vite-node.mjs scripts/measure.ts`.

매 렌더 프레임에 구조 계산을 반복하지 않습니다. 관련 원본 배열/연결부/출력 상태가 바뀔 때 무효화하고, 손상/복구는 4Hz로 처리합니다. 변경 구역만 푸는 증분 솔버는 아직 구현하지 않았습니다.

## WebGL 실측

Chrome, **SwiftShader 소프트웨어 WebGL**, 1440×900, DPR 1, 그림자 켬, 개발 빌드, 시간 정지 실험실. 각 단계 2초 워밍업 후 8초 동안 프레임을 집계했습니다. `gl.info`는 이전 렌더 프레임의 실제 카운터입니다.

| 장면                       | Draw calls | 삼각형 | Geometry | 평균 FPS | 중앙 프레임 / p95 |
| -------------------------- | ---------: | -----: | -------: | -------: | ----------------- |
| 초기 36 플랫폼 / 5 시설    |        120 |  6,292 |      132 |     6.89 | 143.1 / 155.1 ms  |
| 최대 256 플랫폼 / 255 시설 |        564 | 92,840 |      574 |     2.74 | 378.8 / 399.3 ms  |
| 초기화 후                  |        119 |  6,212 |      132 |     6.86 | 146.0 / 160.4 ms  |

[원본 JSON](performance-browser.json). 최대 장면의 표본은 22프레임으로 적으므로 정밀한 분포 추정에는 부족합니다. 원본의 `samples`에 집계 수가 있습니다. 이 수치는 GPU 가속 성능이 아니며 실제 GPU에서 60 FPS 또는 수백 시설의 원활한 플레이를 달성했다고 주장하지 않습니다.

정적 시설/도로 인스턴싱 전 같은 최대 도시에서 2,342 draw calls / 2,352 geometry를 관찰했고, 최적화 후 564 / 574로 줄었습니다. 플랫폼은 이미 인스턴싱되어 있습니다. 개별 애니메이션 발전/부양 장치는 유지합니다. 초기화 뒤 geometry가 132로 돌아왔고 texture 수는 전 과정 2개였습니다. 단일 확장/초기화 주기의 자원 반환 확인이며 장시간 메모리 누수 부재를 입증하는 결과는 아닙니다.

## 확인된 제한과 다음 검증

- 동일 강성 그래프·국소 부양·거리 모멘트의 게임 근사이며 정밀 구조 공학 해석이 아닙니다.
- 물리 엔진 충돌 대신 제한된 잔해 애니메이션을 사용합니다. 잔해는 다른 구조물을 타격하지 않습니다.
- Firefox/Safari, 모바일, 실제 저사양 GPU, 장시간 반복 붕괴/저장 메모리 프로파일링은 미검증입니다.
- 최대 도시의 소프트웨어 렌더링은 느립니다. 실제 GPU 측정 후 동적 발전/부양 모델 추가 인스턴싱, 그림자 품질 조절 등을 판단할 수 있습니다.
- Vite의 Three.js 청크 크기 경고가 남습니다. 장면은 지연 로드하고 DPR을 1.6으로 제한합니다.
- 공개 웹 배포·DNS·인증서는 이 작업 범위에서 변경하지 않았습니다.
